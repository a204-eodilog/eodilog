# [BE] 다음 개발 A·B 분담안 (2026-11-02)

B에게 전달할 다음 개발 순서와 담당 경계다. **이미 합의한 B 작업**과 **이번에 제안하는 후속 분담**을 구분한다. 이 문서는 새 작업의 구현 완료 기록이 아니다.

정산·채팅·기본 나가기의 확정 정책과 기존 코드 확인 결과는 [A → B 정책 답변](to-B-backend-decisions-2026-11-02.md)을 함께 참고한다.

## 1. 지금부터 진행할 순서

| 순서 | A | B | 상태·의존성 |
| --- | --- | --- | --- |
| 현재 | 운영 프로필·Swagger, CORS, 오류 로그, 테스트 프로필 분리 | 정산 계산·이전 계산 조회 | A 로컬 구현·186개 테스트 통과, 이슈별 MR 분리·검토 중. B 정산 정책은 사용자 확정 |
| 다음 | `jobs` 공통 기반 | 채팅 메시지 REST | A jobs 담당은 이번 분담 제안. 정산·채팅 REST는 jobs를 기다리지 않고 진행 가능 |
| 이후 | 장소·지역 API → 개인 즐겨찾기·여행별 장소 저장 | 기본 나가기 | B 나가기는 삭제 기능을 제외한 1단계. 성공 응답·미지원 요청 계약을 먼저 맞춤 |
| 위 기능 이후 | 알림 기반(`events`·`notifications`) | 투표 → 코스 수동 편집 | 이번 후속 분담 제안. 투표·코스는 장소·지역 식별자가 필요 |

**B는 우선 정산부터 시작하면 된다.** 새 제안은 담당·공통 계약을 B와 맞춘 뒤 착수하며, 아래 먼 후속 기능까지 한 번에 구현하는 요청은 아니다.

## 2. A 담당

### A-0. 현재 잔여 설정 — 로컬 구현·검증 완료, 병합 전

| Jira | 작업 |
| --- | --- |
| [EODI-129](https://jira.example.com/browse/EODI-129) | prod 프로필·운영 Swagger/OpenAPI 비활성화 |
| [EODI-130](https://jira.example.com/browse/EODI-130) | 환경변수 기반 CORS, 허용 헤더·X-Trace-Id 노출 |
| [EODI-131](https://jira.example.com/browse/EODI-131) | 메시지·비밀값 없는 제한 스택·cause 타입 오류 로그 |
| [EODI-132](https://jira.example.com/browse/EODI-132) | application-test.yaml·test 프로필 분리 |

실제 웹 프론트 origin은 확인 후 환경별로 지정한다. 설정 구현 완료를 배포·Expo 실연동 완료로 표현하지 않는다.

11/02 검증: 전체 Gradle build 성공, 테스트 186개 실패·오류·건너뜀 0. 이슈별 MR로 분리해 검토하며 Jira는 병합 전까지 진행 중으로 유지한다. 코드 반영 뒤 A-1의 공통 계약을 B와 먼저 맞춘다.

### A-1. jobs 공통 기반 — 담당 제안

- `jobs` 저장 모델·상태 전이, 공통 `JobRef`, `GET /jobs/{jobId}` 권한 검사.
- 작업 등록·실행·성공/실패 기록과 재시도 계약. 요청 키가 필요한 작업은 중복 실행 방지.
- AI 작업과 삭제 작업의 조회 권한을 구분한다. 삭제 요청자는 이탈 후에도 본인 요청의 최소 진행 상태만 볼 수 있게 설계한다.
- B에게 작업 등록 인터페이스·결과 저장 방식·트랜잭션 경계를 먼저 공유한다.
- 공통 기반 구현만으로 AI 호출·사진 삭제·여행 전체 삭제를 완료했다고 보지 않는다. 각 실행기는 해당 기능 담당이 별도로 구현한다.

**착수 전 맞출 것:** 최초 지원할 작업 kind, 실행 방식, 재시도·장애 복구 기준. 존재하지 않는 worker나 가짜 완료 작업을 만들지 않는다.

### A-2. 장소·지역과 저장 — 담당 제안

1. `GET /regions`, `GET /regions/{regionId}`: 검색·상세와 지역 ID 체계.
2. `GET /places`, `GET /places/{placeId}`, `POST /places`: 공급자 검색·로컬 식별자·직접 등록.
3. 개인 즐겨찾기 조회·저장·메모 수정·삭제.
4. 여행별 장소 저장·내 저장 해제·저장자/겹침 조회.

공급자·지역 데이터 출처와 장소 동일성 기준은 먼저 맞춘다. A가 지역·장소 UUID와 DTO를 공유한 뒤 B가 투표·코스에서 재사용한다. 공급자 호출 실패와 검색 결과 없음을 구분한다.

### A-3. 알림 기반 — 담당 제안

- `events`·수신자별 `notifications`, 목록·읽음·숨김·미읽음 수.
- 이벤트 중복 방지와 수신 시점/열람 시점 권한 검사.
- B는 도메인 이벤트를 발행하고 A가 저장·수신자 계산·조회에 연결하는 경계로 맞춘다.
- 투표 알림의 필수 이벤트부터 B와 공유한다. 푸시·알림 묶음·시스템 카드 읽음 동기화는 관련 정책 확인 후 단계적으로 붙인다.

## 3. B 담당

### B-0. 기존 경비 재요청 권한 보완

정산 작업 전 또는 같은 작업에서 경비 등록의 멱등 재요청도 현재 멤버십을 확인하도록 보완한다.

- LEFT·REMOVED·여행 삭제 후 같은 키·본문 재요청은 `404 TRIP_NOT_FOUND`.
- ACTIVE의 정상 재요청은 기존 결과 유지.
- 상세 재현과 검증 항목은 [정책 답변 §6](to-B-backend-decisions-2026-11-02.md)의 B 수정 요청 참조.
- A는 B 구현을 수정하지 않는다.

### B-1. 정산 계산·이전 계산 — 사용자 합의 완료

- `settlements` 및 계산 스냅샷·멤버별 잔액·송금 제안 저장.
- `POST /trips/{tripId}/settlements` 활성화, 현재 계산 상태·재계산 필요 반영.
- 이전 계산 목록·상세 조회.
- 사람별 여행 합산 후 한 번 10원 올림, 원금 순채권 최대자에게 차액 배정, 이력은 여행 삭제까지 보관.
- 비용 버전 충돌·동시 계산·Idempotency-Key·이탈자 포함·잔액 합 0을 검증.

### B-2. 채팅 REST — 사용자 합의 완료

- 방 목록·여행 채팅방 조회, 메시지 저장·sequence 페이지 조회·전송.
- 신규·재참여 ACTIVE 멤버 모두 전체 과거 대화 조회. LEFT·REMOVED 조회/전송 차단.
- clientMessageId·중복 요청 계약, 순서·동시 전송을 검증.
- **실시간 전송 방식은 아직 미정**이다. REST 구현과 분리한다.

### B-3. 기본 나가기 — 사용자 합의 완료

- 경비·사진·메시지를 유지하는 일반 이탈.
- 방장 이탈 시 가장 먼저 참여한 남은 ACTIVE 멤버에게 자동 양도.
- 멤버십·채팅 참여·여행 version을 일관되게 변경.
- 실제 삭제 기능 전에는 삭제 옵션을 무시하고 성공 처리하지 않는다. 마지막 한 명의 이탈도 여행 삭제 기능과 함께 지원한다.

**선행 계약:** 현재 명세의 202/JobRef를 1단계에서 어떻게 제공할지 B가 성공 응답·미지원 오류안을 제시한다. 즉시 완료 응답으로 바꾸는 경우 명세 변경을 먼저 합의한다. jobs가 필요한 계약이면 A-1과 연동한다.

### B-4. 투표 → 코스 수동 편집 — 후속 담당 제안

- A의 지역·장소 계약을 받은 뒤 지역/장소 투표 생성·후보 추가·선택·마감·결과 반영.
- 코스 조회·전체 편집, 버전 충돌 처리.
- 투표 마감 스케줄·코스 변경 이벤트를 A 알림과 연결.
- 이동 경로 공급자·실시간 공동 편집·AI 적용/되돌리기는 정책·연동 계약을 정한 뒤 확장한다.

## 4. 공통 파일·통합 규칙

| 영역 | 주 담당 | 협업 방식 |
| --- | --- | --- |
| SecurityConfig·CORS·프로필·인증 필터 | A | B 공개 API 추가 시 A와 경로·필터 동작 공유 |
| jobs·events·notifications 기반 | A 제안 | B는 공통 인터페이스 사용. 같은 역할을 중복 구현하지 않음 |
| trip·expense·chat·poll·itinerary | B | ACTIVE 권한·여행 잠금·버전 규칙 재사용 |
| region·place·개인/여행 장소 저장 | A 제안 | 지역·장소 DTO와 UUID를 B에게 먼저 공유 |
| 마이그레이션 번호·build.gradle·API 명세 | 해당 변경 담당 | 병합 전 번호·설정 충돌 확인, 명세·Swagger·테스트 함께 반영 |

각 작업은 독립 검증 가능한 기능 단위로 Jira/MR을 나눈다. A-0의 4개 외 후속 Jira 번호는 아직 생성하지 않았으며 임의 번호를 사용하지 않는다.

## 5. 이번 분담에서 확정하지 않는 범위

사진 업로드·분류·평가, 공동 피드·지도·타임라인, 회원 공개 범위·팔로우·취향, AI 기능별 연동, 전체 자료 삭제·회원 탈퇴는 이후 별도 분담한다. 정산·채팅·나가기와 A 장소 기반 진행 상황을 보고 다음 단위를 정한다.

**B 확인 요청:** 위 A-1~3/B-4의 후속 담당 제안과 기본 나가기 응답 계약을 맞추면 된다. 이미 확정한 정산·채팅 정책을 다시 결정할 필요는 없다.
