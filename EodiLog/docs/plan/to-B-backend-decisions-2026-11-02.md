## 3. Q-10 정산 — 확정

### 올림 시점

저장된 원금 분담액을 **사람별로 여행 전체 합산한 뒤 한 번만 10원 단위로 올림**해요. 지출별 올림은 하지 않고, 0원은 0원으로 유지해요. 이탈자의 과거 결제·분담도 포함해요.

### 차액 귀속

차액은 **원금 기준 받을 돈(`결제 합계 - 원금 부담 합계`)이 가장 많은 한 사람**에게 배정해요.

- 동률이면 `joinOrder ASC, memberId ASC`로 정해요.
- 원금 기준 순잔액이 모두 0이면 실제 결제 합계가 가장 큰 사람을 고르고 같은 동률 규칙을 적용해요.
- 경비가 없으면 차액은 0이며 수령자를 만들지 않아요.
- 최종 송금액은 다시 10원 단위로 올리지 않아요. 정산 완료 상태·실제 송금 확인도 추가하지 않아요.

계산 시 `owedMinor`는 올림 부담액, 멤버별 `roundingAdjustmentMinor`는 원금 대비 올림액으로 구분해 주세요. 전체 차액은 수령자의 채권에 한 번만 더해요.

```text
baseOwedMinor = 저장된 원금 분담액의 사람별 합계
owedMinor = baseOwedMinor를 10원 단위로 올린 금액
전체 차액 = Σ(owedMinor - baseOwedMinor)
balanceMinor = paidMinor - owedMinor + (차액 수령자이면 전체 차액, 아니면 0)
```

모든 멤버의 `balanceMinor` 합계는 0이어야 해요.

### 이전 계산 보관

여행이 있는 동안 모두 보관하고, 여행 삭제 시 함께 정리해요. 원본 경비를 수정·삭제해도 과거 계산 스냅샷을 덮어쓰지 않아요. 물리 삭제 시점은 Q-11 삭제 작업 정책에서 별도로 정해요.

### 예시 보정

현재 구현은 경비마다 원금의 1원 잔여를 참여 순으로 배분해요. 같은 세 사람이 10,001원 경비 3건을 나누면 원금 합계는 **10,002 / 10,002 / 9,999원**이에요. 여행 합산 후 올림하면 **10,010 / 10,010 / 10,000원**, 전체 차액은 **17원**이에요.

B 전달 문서의 사람별 10,001원·차액 27원 예시는 현재 정수 분담 방식에 맞춰 보정해 주세요. 기존 원금 분담 정책을 바꾸자는 뜻은 아니에요.

정책은 확정됐지만 계산 기능은 아직 구현 전이에요. B의 정산 구현에서 현재 `SETTLEMENT_POLICY_PENDING` 차단을 해제하고 명세·Swagger·테스트를 함께 반영해 주세요.

## 5. Q-11 나가기 — 기본 기능부터

사용자는 **사진·메시지를 남기는 기본 나가기부터** 진행하기로 했어요.

- 일반 이탈은 경비·사진·메시지를 유지하고, 멤버십 LEFT와 채팅 참여 종료를 같은 트랜잭션에서 처리해요.
- 방장이 나가면 남은 ACTIVE 멤버 중 먼저 참여한 사람에게 자동 양도해요.
- 사진·메시지 삭제 옵션은 실제 삭제 처리 기능을 갖춘 뒤 지원해요. 옵션을 받고 무시한 채 성공으로 응답하지는 않아요.
- 마지막 한 명의 나가기는 여행 삭제 처리까지 갖춘 뒤 지원해요. 그전에는 상태를 바꾸거나 완료됐다고 응답하지 않아요.

현재 명세는 삭제 옵션과 202·`JobRef`를 전제로 하므로, **기본 나가기 성공 응답과 미지원 요청 응답을 먼저 제안해 주세요.** 1단계 계약을 맞춘 뒤 명세·Swagger·테스트와 함께 구현하면 돼요. 실제로 실행하지 않는 정리 작업에 가짜 작업 ID를 반환하지는 않아요.

메시지 본문만 삭제할지 행을 삭제할지, 강제 이탈자의 자료 처리, 최종 여행 삭제의 물리 보존 기간은 이번에 확정하지 않았어요.

### 경비 멱등 재요청 권한 보완 요청

`ExpenseService.createExpense`에서 기존 `Idempotency-Key` 응답을 재생하면 신규 생성 콜백을 건너뛰고, 콜백 안에 있는 현재 멤버십 검사도 빠져요.

따라서 **경비 등록 → 이탈/내보내기 → 같은 키·본문 재요청** 시 저장된 경비 응답을 받을 수 있어요. 여행 삭제 후에도 같은 경로가 있어요.

- LEFT·REMOVED·여행 삭제 후 재요청은 `404 TRIP_NOT_FOUND`.
- 정상 ACTIVE 멤버의 같은 키·본문 재요청은 기존 응답 유지.
- 기존 멱등 기록·여행 행 잠금 순서를 고려해서 교착을 만들지 않도록 처리.
- 위 권한 변경 후 재요청 회귀 테스트 추가.

**A가 임시로 만들었던 B 코드 수정은 모두 되돌렸어요. 이 보완은 B에게 요청하는 항목이에요.**
