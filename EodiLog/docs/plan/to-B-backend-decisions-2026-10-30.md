## 2. !50 API 명세 변경에 대한 답변

- 방장 양도·동행 내보내기 시 여행 `version`을 올리는 정책에 동의해요.

- **아직 코드 대조 리뷰를 완료한 것은 아니므로**, `backend-b-followup.md` §5·§6의 A 리뷰 대기 문구는 결과 전달 후 정리해 주세요.

## 3. UUID와 문자열 길이

현재 구현된 문자열 제한에 동의해요.

| 항목 | A 답변 |
| --- | --- |
| UUID | 신규 생성 ID는 v7로 통일. A 인증 코드 전환은 MR !59로 게시 |
| 여행 이름 | 앞뒤 공백 제거 후 1~200자 |
| 준비물 이름 | 최대 255자 |
| 닉네임 | 앞뒤 공백 제거 후 1~50자 |

- 기존 v4 ID는 유지해요.
- A JDBC 인증은 Hibernate `UuidVersion7Strategy`를 감싼 `global.id.UuidV7`을 사용해요. B JPA의 VERSION_7과 같은 전략이에요.
- API 명세 §10의 UUID 미정 문구도 정리했어요. 다른 문자열 제한 전체 확정과 !50 코드 대조 리뷰 완료를 뜻하지는 않아요.

## 4. 작업 분담 및 현재 상태

| 담당 | 작업 |
| --- | --- |
| A | UUIDv7·토큰 갱신/로그아웃 MR 게시. 운영 프로필·Swagger 비활성화·CORS 후속 |
| B | 경비 CRUD·정산 조회 dev 반영 확인 |

- B의 초대 미리보기 공개 경로와 A의 refresh 공개 경로가 함께 유지되도록 `SecurityConfig` 변경을 합쳤어요. 초대 생성·수락은 인증을 유지해요.
- 로그인 여부에 따라 초대자 카드가 달라지는 초대 미리보기는 BearerFilter를 그대로 거치고, refresh는 BearerFilter를 건너뛰어요.
- **사용자 확정(10/30): 방장 포함 ACTIVE 최대 20명, 초대 링크 발급 후 7일(168시간) 유효.** 수락 시 정원을 확인하고, 동시 수락으로도 20명을 초과하지 않게 처리해요. 이탈·내보내기로 빈자리가 생기면 다시 참여할 수 있어요.
- ACTIVE 멤버 누구나 링크를 재발급할 수 있고, 재발급하면 이전 링크는 즉시 무효화해요. 링크 만료·재발급은 기존 참여자에게 영향을 주지 않아요.
- dev의 EODI-125를 확인했어요. 7일·20명은 구현됐지만 현재 `InvitationService.createInvitation`은 여러 링크를 각각 만료까지 유지해요. **재발급 시 이전 링크 즉시 무효화 정책은 B의 추가 반영이 필요해요.** 이번 A 인증 작업에서 초대 구현을 바꾸지는 않았어요.
- 초대 수락과 채팅 참여 정보 생성은 같은 트랜잭션에서 처리하고, 재참여라면 `chat_participants.left_at`을 해제해야 한다는 점 확인했어요.
- 나가기·REST 채팅의 담당과 선행 정책은 이번 답변에서 확정하지 않아요.

## 5. 공통 설정과 규칙에 대한 답변

### 운영 설정·CORS

- 운영 프로필에서 Swagger UI와 OpenAPI 문서를 비활성화하는 방향에 동의해요.
- CORS 허용 헤더는 `Authorization`, `Content-Type`, `Idempotency-Key`, 노출 헤더는 `X-Trace-Id`를 포함해요.
- **허용 origin 목록은 아직 미정**이에요. 프론트 개발·배포 주소를 확인한 뒤 환경별로 정해요.
- 토큰 정책은 액세스 1시간, 리프레시는 매 갱신 시점부터 새로 2주예요. 이전 두 토큰은 즉시 폐기하며 사용한 refresh 재사용 시 해당 로그인 계열을 폐기해요. 다른 기기는 유지해요.

### 오류 로그

- 예외 메시지와 비밀값을 제외하면서, 우리 코드 위치까지 제한된 스택 프레임과 cause 체인의 예외 타입을 남기는 방향에 동의해요.
- 구체적인 프레임 수·cause 깊이 제한은 구현 시 정하고 공유할게요.

### 패키지·테스트 설정

- 새 도메인은 기존 다수 도메인처럼 루트 패키지 아래에 두는 방향에 동의해요.
- 기존 `domain.auth` 이동은 별도 정리 작업으로 다루고, 기능 작업과 동시에 대규모 이동하지 않아요.
- 테스트 설정은 본 설정을 통째로 가리는 방식에서 `application-test.yaml`과 test 프로필로 분리하는 방향에 동의해요. 실제 전환은 별도 변경으로 검증해요.
- !55의 AGENTS.md·ERD 설명은 A가 확인 후 오류가 있으면 별도로 전달할게요.
