# Feature Specification: 탭·화면 전환과 진동

**Feature Branch**: `feature/EODI-297-transitions-haptics` (Jira EODI-297)

**Created**: 2026-11-11

**Status**: Implemented — 휴대폰 확인 대기(tasks T009)

**Input**: User description: "탭·화면 전환과 진동. 탭 사이 전환 넣기. 상세 화면은 옆에서, 입력 화면은 아래에서 들어오게 하기. 진동 다섯 종류 넣기(가볍게, 선택, 성공, 경고, 실패)."

**근거 문서**: 2026-11-11 계획 세션에서 정한 표(진동과 넣는 곳, 탭 전환 120~150ms)

## Clarifications

### Session 2026-11-11

- Q: 아래에서 올라오는 입력 화면은 어디인가? → A: 내 담당인 새 여행 만들기다. 투표 열기는 시트다. 다른 담당의 입력 화면은 바꾸지 않는다. (가정 — 사용자 확인 필요, Q-19-1)
- Q: 주요 버튼은 무엇인가? → A: 공통 버튼 가운데 파랑·빨강이고 큰 것(높이 48, 56)이다. 작은 버튼과 보조 버튼은 울리지 않는다. (가정 — 사용자 확인 필요, Q-19-2)
- Q: 체크와 고르기의 진동은 어디서 울리나? → A: 그려지는 체크가 방금 체크됐을 때 울린다. 준비물 체크, 투표 고르기, 그룹 즐겨찾기 장소 고르기, 날씨 대안 고르기가 한꺼번에 따른다. 화면을 열 때 이미 체크돼 있던 것은 울리지 않는다. (가정 — 사용자 확인 필요, Q-19-3)
- Q: 성공 진동은 어디에 넣나? → A: 내 담당인 여행 만들기, 투표 열기, 여행 설정 저장, 변경안 적용에 넣는다. (2026-11-11 계획 세션에서 정함)
- Q: 코스 순서 끌기의 진동은? → A: 지금 코스 순서는 위·아래 버튼으로 바꾸고 끌기가 없어 넣지 않는다. (가정 — 사용자 확인 필요, Q-19-4)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 화면이 방향을 가지고 바뀐다 (Priority: P2)

탭을 바꾸면 짧게 겹쳐 바뀌고, 상세 화면은 옆에서 밀려 들어오고, 새로 만드는 화면은 아래에서 올라온다.

**Why this priority**: 화면이 어디서 왔는지 알면 뒤로 가는 방향도 알 수 있다.

**Independent Test**: 탭을 바꿔 겹쳐 바뀌는지, 여행을 눌러 옆에서 들어오는지, 새 여행을 눌러 아래에서 올라오는지 본다.

**Acceptance Scenarios**:

1. **Given** 탭 화면에서, **When** 다른 탭을 누르면, **Then** 150ms 동안 겹쳐 바뀐다.
2. **Given** 목록에서, **When** 상세 화면을 열면, **Then** 옆에서 밀려 들어온다.
3. **Given** 여행 탭에서, **When** 새 여행을 누르면, **Then** 아래에서 올라온다.

---

### User Story 2 - 손끝으로 결과를 안다 (Priority: P2)

탭을 바꾸거나 주요 버튼을 누르면 가볍게, 체크하거나 고르면 톡, 일이 잘 끝나면 성공, 지우기·나가기를 물으면 경고, 실패하면 실패 진동이 온다.

**Why this priority**: 화면을 보지 않아도 눌렸는지, 됐는지 안다.

**Independent Test**: 휴대폰에서 탭 바꾸기, 준비물 체크, 여행 만들기, 여행 나가기 시트, 연결을 끊고 저장하기를 해 보고 진동이 다른지 느껴 본다.

**Acceptance Scenarios**:

1. **Given** 다른 탭을 누를 때, **When** 탭이 바뀌면, **Then** 가볍게 울린다. 같은 탭을 다시 누르면 울리지 않는다.
2. **Given** 큰 파랑·빨강 버튼을 누를 때, **When** 눌리면, **Then** 가볍게 울린다.
3. **Given** 체크하거나 칩을 고를 때, **When** 골라지면, **Then** 선택 진동이 울린다.
4. **Given** 여행 만들기, 투표 열기, 설정 저장, 변경안 적용이 끝났을 때, **When** 성공하면, **Then** 성공 진동이 울린다.
5. **Given** 지우기·나가기 확인 시트가 뜰 때, **When** 나타나면, **Then** 경고 진동이 울린다.
6. **Given** 실패 안내가 뜰 때, **When** 나타나면, **Then** 실패 진동이 울린다.
7. **Given** 작은 버튼이나 보조 버튼을 누를 때, **When** 눌리면, **Then** 울리지 않는다.

---

### Edge Cases

- 휴대폰에서 터치 진동을 꺼 두었으면 울리지 않는다.
- 진동이 실패해도 화면 동작은 그대로 된다.
- 웹에는 진동이 없다.
- 휴대폰의 애니메이션 삭제가 켜져 있으면 화면 전환은 기기가 끈다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 탭 사이는 150ms 동안 겹쳐 바뀌어야 한다.
- **FR-002**: 탭 위에 쌓이는 화면은 옆에서 밀려 들어와야 한다.
- **FR-003**: 새 여행 만들기는 아래에서 올라와야 한다.
- **FR-004**: 진동은 가볍게, 선택, 성공, 경고, 실패 다섯 이름으로만 불러야 한다.
- **FR-005**: 탭을 바꿀 때와 주요 버튼을 누를 때 가볍게 울려야 한다.
- **FR-006**: 방금 체크했을 때와 칩을 고를 때 선택 진동이 울려야 한다.
- **FR-007**: 여행 만들기, 투표 열기, 여행 설정 저장, 변경안 적용이 성공하면 성공 진동이 울려야 한다.
- **FR-008**: 지우기·나가기 확인 시트가 뜰 때 경고 진동이 울려야 한다.
- **FR-009**: 실패 안내가 뜰 때 실패 진동이 울려야 한다.
- **FR-010**: 진동이 실패하거나 없는 환경에서도 화면 동작이 막히지 않아야 한다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 다섯 가지 진동이 서로 다른 진동을 부른다.
- **SC-002**: 진동이 실패해도 오류가 화면으로 올라오지 않는다.
- **SC-003**: 자동 테스트 전체와 타입 검사, 코드 규칙 검사가 통과한다.

## Assumptions

- 진동의 세기와 느낌, 전환이 끊기는지는 휴대폰에서만 알 수 있다. 사용자 확인으로 남긴다.
- 채팅방은 열 때 무거워 전환 중 끊길 수 있다. 끊김 재기 주제에서 본다.
