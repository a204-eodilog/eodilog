# Research: 시험 데이터에 사진 넣기

## R1. 사진 칸 조사 (2026-11-11)

화면이 사진을 그리는 길은 모두 `src/lib/asset-image.ts`의 `assetSource`를 지난다. 테스트 모드에서는 인터넷 전체 주소가 아니면 `null`을 돌려줘 빈 그림 표시가 된다.

| 화면·칸 | 주소를 만드는 곳 | 시험 데이터 값 | 이번에 사진이 보이나 |
| --- | --- | --- | --- |
| 여행 사진 목록·크게 보기 (S31) | `photoPath(assetId)` | `asset-seed-1` ~ `10` | 보인다 |
| 내 여행 기록의 사진 (S38) | `photoPath(assetId)` | 여행 사진과 같다 | 보인다 |
| 피드 상세 표지·사진 3장·장소 사진 (S07) | 피드의 `photos[].imageUrl` | `/assets/sample-N/download?feedId=` | 보인다 |
| 마이페이지·친구에게 보이는 모습의 여행 카드 | 피드의 `photos[].imageUrl` | 피드 목록에 사진이 있으면 | 피드에 사진이 있으면 보인다 |
| 타임라인 요약 표지 (S42) | `coverAssetId` | 가짜 서버 응답에 값을 넣는다 | 값을 넣으면 보인다 |
| 얼굴 사진 (공통 Avatar) | `profileImageUrl` | 모두 `null` | 다른 사람 일부에 넣으면 보인다 |
| 홈의 여행지 카드·피드 카드 (S05·S06) | `home-rules.ts`가 늘 `null`로 둔다 | 서버 응답에 사진 주소가 없고 `coverPhotoId`만 있다 | 안 보인다. 화면 규칙 코드를 고쳐야 한다 |
| 요즘 뜨는 여행지·여행지 정보 (N2·N3) | `destination-rules.ts`가 늘 `null`·빈 목록으로 둔다 | 서버 응답에 사진 칸이 없다 | 안 보인다 |
| 장소 정보 시트 | `place/info.ts`가 늘 `null`로 둔다 | 서버 응답에 사진 칸이 없다 | 안 보인다 |
| 추천·그룹 즐겨찾기 장소 줄 | 사진 칸이 없다 | - | 해당 없음 |

- **Decision**: 위 표에서 "보인다"인 칸만 이번에 채운다. 나머지는 다른 담당의 화면 규칙 코드가 사진 주소를 늘 비워 두는 곳이라, 시험 데이터만으로는 채울 수 없다. 확인 기록에 적어 넘긴다.

## R2. 샘플 사진 주소로 바꾸는 곳

- **Decision**: `src/lib/mock-photo.ts`에 `mockPhotoUrl(path)`를 두고, `assetSource`가 테스트 모드일 때 이 함수를 먼저 부른다. 시험 사진 주소(자산 id가 `sample-`이나 `asset-seed-`로 시작)면 `https://picsum.photos/seed/{자산 id}/600/600`을 돌려주고, 아니면 `null`이다.
- **Rationale**: 화면 코드를 하나도 고치지 않는다. 자산 id를 씨앗으로 써서 같은 항목은 늘 같은 사진, 다른 항목은 다른 사진이 된다. 방금 올린 사진의 자산 id는 다른 모양이라 바뀌지 않는다(Q-14-3).
- **Alternatives considered**: 시험 데이터에 인터넷 전체 주소를 직접 넣기 — 여행 사진처럼 화면이 자산 id로 주소를 만드는 칸에는 넣을 수 없다. 사진 파일을 앱에 넣기 — 앱이 커지고, 사용자가 인터넷 샘플 주소로 정했다.

## R3. 사진을 못 받았을 때

- 공통 Avatar는 `source`가 있으면 사진만 그려, 받기에 실패하면 빈 동그라미가 된다.
- **Decision**: Avatar가 받기 실패(`onError`)를 기억해 글자 얼굴로 돌아간다. 주소가 바뀌면 다시 시도한다.
- 다른 사진 칸은 구현 뒤 인터넷을 막고 열어 `photo-check.md`에 적는다.
