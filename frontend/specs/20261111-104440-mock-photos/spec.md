## Clarifications

### Session 2026-11-11

- Q: 샘플 사진은 어디서 받나? → A: 주소에 넣은 글자에 따라 늘 같은 사진을 주는 공개 샘플 사진 서비스(picsum.photos)를 쓴다. 사진 파일을 앱에 넣지 않는다. (가정 — 사용자 확인 필요, Q-14-1)
- Q: 화면마다 사진 주소를 만드는 방식이 다르다. 어디를 고치나? → A: 화면 코드는 고치지 않는다. 사진 주소를 화면용으로 바꾸는 공통 함수가 테스트 모드의 시험 사진 주소를 샘플 사진 주소로 바꾼다. 시험 데이터에는 시험 사진 주소만 채운다. (가정 — 사용자 확인 필요, Q-14-2)
- Q: 테스트 모드에서 내가 방금 올린 사진도 샘플 사진으로 보이나? → A: 아니다. 시험 데이터에 처음부터 들어 있던 사진만 샘플 사진으로 보인다. 방금 올린 사진은 지금처럼 빈 그림 표시다. (가정 — 사용자 확인 필요, Q-14-3)
- Q: 프로필 사진은 모두에게 넣나? → A: 나는 넣지 않는다. 내 얼굴의 연파랑 구분과 프로필 사진 올리기 확인을 그대로 두기 위해서다. 다른 사람은 절반쯤만 넣어 사진 얼굴과 글자 얼굴이 섞인 모습을 볼 수 있게 한다. (가정 — 사용자 확인 필요, Q-14-4)
- Q: 사진을 못 받았을 때 빈 칸으로 남는 곳은? → A: 공통 얼굴 부품은 글자 얼굴로 돌아가게 고친다. 다른 담당 화면의 사진 칸은 고치지 않고 확인 결과만 적는다. (가정 — 사용자 확인 필요, Q-14-5)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 테스트 모드에서 사진이 든 화면을 본다 (Priority: P1)

테스트 모드로 앱을 켜면 홈의 여행지·피드 카드, 피드 상세, 여행 사진 목록, 타임라인, 다른 사람 프로필, 장소 정보에 사진이 보인다. 빈 그림 표시만 가득하던 화면에서 실제 모습에 가까운 화면을 볼 수 있다.

**Why this priority**: 이 작업의 목적이다. 사진이 있어야 카드 비율, 글자와 사진의 겹침, 얼굴 묶음 모양을 확인할 수 있다.

**Independent Test**: 인터넷이 되는 상태에서 테스트 모드로 홈, 피드 상세, 여행 사진, 타임라인, 친구 목록을 열어 사진이 보이는지 확인한다. 앱을 껐다 켜서 같은 칸에 같은 사진이 나오는지 본다.

**Acceptance Scenarios**:

1. **Given** 테스트 모드이고 인터넷이 될 때, **When** 사진이 들어가는 화면을 열면, **Then** 시험 데이터의 사진 칸에 사진이 보인다.
2. **Given** 같은 화면을 다시 열거나 앱을 다시 켰을 때, **When** 같은 항목을 보면, **Then** 같은 사진이 보인다.
3. **Given** 서로 다른 항목일 때, **When** 한 화면에 함께 보이면, **Then** 대부분 서로 다른 사진이다.
4. **Given** 테스트 모드가 아닐 때, **When** 화면을 열면, **Then** 사진 주소 처리는 지금과 같다.

---

### User Story 2 - 사진이 없거나 못 받아도 화면이 깨지지 않는다 (Priority: P2)

인터넷이 없거나 사진을 못 받으면 지금의 빈 그림 표시나 글자 얼굴이 보인다. 빈 칸이나 깨진 그림이 남지 않는다.

**Why this priority**: 실제 서버에서도 사진은 늦게 오거나 실패한다. 그때의 모습을 테스트 모드에서 미리 볼 수 있어야 한다.

**Independent Test**: 인터넷을 끊고 테스트 모드로 같은 화면들을 열어 사진 칸마다 무엇이 보이는지 적는다.

**Acceptance Scenarios**:

1. **Given** 사진을 못 받았을 때, **When** 얼굴 사진 자리를 보면, **Then** 이름 첫 글자 얼굴이 보인다.
2. **Given** 사진을 못 받았을 때, **When** 다른 사진 칸을 보면, **Then** 칸마다 무엇이 보이는지가 확인 기록에 적혀 있다.
3. **Given** 시험 데이터에 사진이 없는 항목일 때, **When** 화면을 열면, **Then** 지금처럼 빈 그림 표시가 보인다.

---

### Edge Cases

- 테스트 모드에서 방금 올린 사진은 샘플 사진으로 바뀌지 않는다.
- 이미 인터넷 전체 주소이거나 기기 안의 주소인 사진은 지금처럼 그대로 쓴다.
- 나의 프로필 사진은 비어 있다. 프로필 사진을 올리면 지금과 같이 동작한다.
- 사진이 없는 항목도 일부 남겨 빈 그림 표시를 볼 수 있게 한다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 테스트 모드에서 시험 데이터의 사진 주소는 인터넷 샘플 사진으로 보여야 한다.
- **FR-002**: 같은 시험 사진 주소는 언제나 같은 샘플 사진으로 바뀌어야 한다.
- **FR-003**: 서로 다른 시험 사진 주소는 서로 다른 샘플 사진 주소로 바뀌어야 한다.
- **FR-004**: 테스트 모드가 아니면 사진 주소 처리는 바뀌지 않아야 한다.
- **FR-005**: 테스트 모드에서도 시험 데이터가 아닌 사진 주소(방금 올린 사진 등)는 지금처럼 그리지 않아야 한다. 인터넷 전체 주소와 기기 안 주소는 그대로 써야 한다.
- **FR-006**: 시험 데이터는 다음 칸에 시험 사진 주소를 가져야 한다: 홈의 여행지 카드와 피드 카드, 피드 상세의 표지와 장소 사진, 여행 사진 목록, 타임라인 표지, 다른 사람의 프로필 사진, 장소 정보 사진, 여행지 정보 사진.
- **FR-007**: 나의 프로필 사진은 비워 두어야 한다.
- **FR-008**: 다른 사람의 프로필 사진은 일부만 채워 사진 얼굴과 글자 얼굴이 함께 보여야 한다.
- **FR-009**: 공통 얼굴 부품은 사진을 못 받으면 이름 첫 글자 얼굴로 돌아가야 한다.
- **FR-010**: 사진을 못 받았을 때 칸마다 무엇이 보이는지 확인해 기록해야 한다. 다른 담당 화면의 사진 칸은 고치지 않는다.

### Key Entities

- **시험 사진 주소**: 시험 데이터에 든 사진 주소. 테스트 모드에서만 샘플 사진 주소로 바뀐다.
- **사진 칸 목록**: 화면, 칸, 주소를 만드는 방식, 못 받았을 때의 모습으로 이루어진 표.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 테스트 모드에서 사진 칸 목록의 모든 칸 종류에 사진이 한 장 이상 보인다.
- **SC-002**: 같은 항목을 열 번 열어도 같은 사진이 나온다.
- **SC-003**: 테스트 모드가 아닐 때의 사진 주소 처리 테스트가 그대로 통과한다.
- **SC-004**: 사진을 못 받았을 때 얼굴 사진 자리에 글자 얼굴이 보인다.
- **SC-005**: 자동 테스트 전체와 타입 검사, 코드 규칙 검사가 통과한다.

## Assumptions

- 샘플 사진 서비스는 누구나 쓸 수 있는 공개 서비스다. 인터넷이 없거나 그 서비스가 멈추면 사진은 보이지 않는다.
- 시험 데이터 파일은 여러 담당이 함께 고치는 파일이다. 사진 주소 칸만 채우고 다른 값은 바꾸지 않는다.
- 추천·즐겨찾기 장소 줄에는 사진 칸이 없다. 장소 사진은 장소 정보 시트에만 있다. 조사에서 다르면 칸 목록에 더한다.
- 휴대폰 확인은 사용자 몫이다.
