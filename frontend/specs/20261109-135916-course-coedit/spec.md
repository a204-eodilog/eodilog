## Clarifications

### Session 2026-11-09

- Q: 코스 실시간 이벤트를 받나? → A: 전송 규격이 Q-15로 정해지지 않아 구독하지 않는다. 대신 공유 실시간 연결이 끊겼다가 다시 연결되는 순간과 [완료] 저장이 409로 거절되는 순간에 최신 코스를 다시 받아 비교한다 (가정 — 사용자 확인 필요, Q-8-1)
- Q: 다른 동행의 변경과 내 변경은 어떤 단위로 합치나? → A: 일차 단위. 처음 코스와 비교해 동행이 고친 날과 내가 고친 날이 겹치지 않으면 최신 코스에 내가 고친 날만 다시 얹고, 겹치면 확인 상자를 띄운다 (가정 — 사용자 확인 필요, Q-8-2)
- Q: 합친 뒤 바로 저장하나? → A: 저장하지 않는다. 합친 초안을 보여 주고 "세은님이 다른 날을 고쳐서 최신 코스에 내 변경을 다시 얹었어요" 안내를 띄운다. 확인한 뒤 [완료]를 다시 누른다 (가정 — 사용자 확인 필요, Q-8-3)
- Q: 확인 상자의 [내 것으로 덮기]는 무엇을 덮나? → A: 내가 고친 날만 내 것으로 덮고, 동행이 다른 날에 고친 것은 남긴다. 동행이 그 사이 지운 항목을 내가 남겨 두었으면 새 항목으로 다시 넣는다. 덮은 뒤 바로 저장한다 (가정 — 사용자 확인 필요, Q-8-4)
- Q: 지금 편집 중인 동행 표시는? → A: 디자인 201-13453의 "세은님도 이 코스를 고치고 있어요" 줄을 부품으로 만들고 미리보기에서 보인다. 누가 편집 중인지 알려 줄 실시간 정보가 없어 실제 화면에는 아직 띄우지 않는다 (가정 — 사용자 확인 필요, Q-8-5)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 먼저 저장한 동행이 있을 때 내 변경 지키기 (Priority: P1)

코스를 고치고 [완료]를 눌렀는데 다른 동행이 그 사이 먼저 저장했다. 동행의 코스를 덮어쓰지 않으면서 내가 고친 것도 잃지 않는다.

**Why this priority**: 지금은 충돌하면 내 변경을 버리고 최신 코스로 바꿔 버린다. 함께 고치는 여행에서 가장 자주 생기는 손실이다.

**Independent Test**: 가짜 서버에서 다른 동행이 2일차를 고친 뒤 내가 1일차를 고치고 [완료]를 누르면, 1일차는 내 것, 2일차는 동행 것인 초안이 보이고 아직 저장되지 않는다.

**Acceptance Scenarios**:

1. **Given** 내가 1일차를 고쳤고 동행이 먼저 2일차만 고쳐 저장했다, **When** [완료]를 누르면, **Then** 최신 코스에 내 1일차를 다시 얹은 초안이 보이고 "세은님이 다른 날을 고쳐서 최신 코스에 내 변경을 다시 얹었어요. 확인하고 완료를 눌러 주세요"가 뜬다. 다시 [완료]를 누르면 저장된다.
2. **Given** 나와 동행이 같은 1일차를 고쳤다, **When** [완료]를 누르면, **Then** "세은님이 먼저 코스를 바꿨어요 / 같은 곳을 고쳤어요. 최신 코스를 확인해 주세요" 확인 상자와 [내 것으로 덮기]·[최신 코스 보기]가 보인다.
3. **Given** 확인 상자, **When** [최신 코스 보기], **Then** 내 변경을 버리고 최신 코스로 초안을 채운다.
4. **Given** 확인 상자, **When** [내 것으로 덮기], **Then** 내가 고친 날은 내 것, 나머지 날은 최신 코스로 저장하고 코스 화면으로 돌아간다.

---

### User Story 2 - 함께 편집 중 연결이 끊겼다 돌아옴 (Priority: P1)

코스를 고치는 동안 연결이 끊겼다가 돌아왔다. 그 사이 동행이 코스를 바꿨으면 [완료]를 누르기 전에 알게 된다.

**Why this priority**: Figma 201-13453 상태이고, 끊긴 동안의 변경을 조용히 잃지 않아야 한다는 API 명세 요구다.

**Independent Test**: 테스트 모드에서 편집 중 연결을 끊고 동행 저장을 흉내 낸 뒤 다시 연결하면, 같은 날을 고쳤을 때 확인 상자가 뜬다.

**Acceptance Scenarios**:

1. **Given** 고친 것이 있는 초안, **When** 연결이 끊겼다가 다시 연결되고 코스 version이 바뀌었으면, **Then** User Story 1과 같은 규칙으로 합치거나 확인 상자를 띄운다.
2. **Given** 고친 것이 없는 초안, **When** 다시 연결되고 코스가 바뀌었으면, **Then** 안내 없이 최신 코스로 바뀐다.
3. **Given** 다시 연결됐지만 코스 version이 그대로, **Then** 아무 일도 없다.

---

### User Story 3 - 지금 편집 중인 동행 표시 (Priority: P3)

다른 동행도 같은 코스를 고치고 있으면 "세은님도 이 코스를 고치고 있어요" 줄이 일차 탭 아래에 보인다.

**Why this priority**: 실시간 정보가 없어 지금은 부품과 미리보기까지만 한다 (Q-8-5).

**Independent Test**: /dev/course-coedit 미리보기의 편집 중 동행 상태에서 줄이 보인다.

**Acceptance Scenarios**:

1. **Given** 편집 중 동행 한 명, **Then** 얼굴과 "세은님도 이 코스를 고치고 있어요".
2. **Given** 두 명 이상, **Then** "세은님 외 1명도 이 코스를 고치고 있어요".

### Edge Cases

- 409 뒤 최신 코스를 받지 못하면 초안을 그대로 두고 "최신 코스를 받지 못했어요. 다시 시도해 주세요"를 띄운다.
- 마지막으로 고친 동행을 알 수 없거나 나간 동행이면 "다른 동행"으로 부른다.
- 내가 고친 날에 남긴 항목을 동행이 지웠으면 합칠 때 새 항목으로 다시 넣는다. 같은 항목이 두 날에 생기지 않는다.
- 동행이 기간을 바꿔 일수가 달라졌으면 많은 쪽 일수에 맞춘다.
- [내 것으로 덮기] 저장이 또 409면 다시 최신을 받아 같은 규칙을 한 번 더 적용한다.
- 직접 만든 코스나 추천안을 아직 한 번도 저장하지 않았으면 모든 날을 내가 고친 날로 본다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 다른 동행의 저장을 덮어쓰지 않아야 한다. [내 것으로 덮기]를 고른 때만 최신 version으로 다시 저장한다.
- **FR-002**: 저장 충돌이면 최신 코스를 받아 처음 코스와 비교하고, 서로 다른 날만 고쳤으면 내 변경을 다시 얹은 초안을 보이며 안내해야 한다.
- **FR-003**: 같은 날을 고쳤으면 디자인 201-13453의 확인 상자를 띄워야 한다. 제목에 마지막으로 고친 동행 이름을 넣는다.
- **FR-004**: 공유 실시간 연결이 끊겼다가 다시 연결되면 편집 중인 코스의 최신 version을 확인해 FR-002·FR-003을 적용해야 한다.
- **FR-005**: 고친 것이 없으면 다시 연결 뒤 바뀐 코스로 조용히 맞춰야 한다.
- **FR-006**: 합친 코스는 같은 항목이 두 번 들어가지 않고, 저장 규칙(날짜별 순서, 인접 쌍마다 구간 하나)을 지켜야 한다.
- **FR-007**: 편집 중 동행 표시 부품을 만들고 미리보기에서 보여야 한다. 실시간 정보가 생기기 전에는 화면에 띄우지 않는다.
- **FR-008**: 실시간 코스 이벤트의 형식을 지어내지 않는다.
- **FR-009**: 확인 상자, 합친 뒤, 편집 중 동행 표시를 서버 없이 미리보기에서 볼 수 있어야 한다.

### Key Entities

- **처음 코스**: 편집을 시작하거나 마지막으로 맞춘 저장 코스. 누가 어느 날을 고쳤는지 가리는 기준.
- **고친 날**: 처음 코스와 비교해 항목, 순서, 시각, 머무는 시간, 구간 수단이 다른 일차.
- **합친 초안**: 최신 코스에 내가 고친 날만 다시 얹은 초안. 시작 version은 최신 코스의 version.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 서로 다른 날을 고친 충돌에서 내 변경과 동행 변경이 둘 다 100% 남는다(규칙 테스트).
- **SC-002**: 어떤 합친 초안도 같은 항목이 두 번 들어가거나 저장 규칙 오류가 나지 않는다(규칙 테스트).
- **SC-003**: 연결이 돌아온 뒤 3초 안에 바뀐 코스를 알아챈다.
- **SC-004**: 확인 상자, 합친 뒤, 편집 중 동행 표시 상태를 미리보기에서 모두 볼 수 있다.

## Assumptions

- 백엔드에는 코스 실시간 이벤트, 접속 중 멤버, 편집 잠금이 없다. Q-15가 정해지면 같은 비교 규칙에 이벤트를 연결한다 (Q-8-1).
- 코스 응답의 updatedByMemberId로 마지막으로 고친 동행을 찾는다.
- 다시 연결 감지는 채팅에서 만든 공유 연결 상태를 쓴다. 앱이 백그라운드에서 돌아오는 것도 다시 연결로 본다.
- 코스 변경 알림 묶음(Q-16)은 12번 알림 주제다.
