# Research: 코스 함께 편집

## R1 실시간 이벤트 없이 바뀐 코스 알아채기
- Decision: 저장 409와 공유 연결의 다시 연결 순간에 GET /trips/{tripId}/itinerary로 최신 코스를 받는다.
- Rationale: API 명세는 코스 실시간 규격을 Q-15로 남겼고 백엔드 destinations에도 코스가 없다. 다시 연결 순간은 채팅에서 만든 연결 상태(reconnecting·paused → connected)로 알 수 있다.
- Alternatives: 일정 간격 다시 받기는 서버 부담과 배터리 때문에 뺐다. 이벤트 형식 가정은 지시에서 금지.

## R2 합치는 단위
- Decision: 일차 단위. 날마다 장소 ID, 시작 시각, 머무는 시간, 인접 쌍 수단을 이어 붙인 값으로 처음 코스와 비교한다.
- Rationale: 저장이 전체 교체라 항목 단위 합치기는 순서와 구간 규칙을 다시 맞춰야 해 틀리기 쉽다. 같은 날이 겹치는 경우만 사람이 고른다.
- Alternatives: 항목 단위 3방향 합치기는 서버 규격(Q-15)이 정해진 뒤.

## R3 같은 항목이 두 번 들어가지 않게
- Decision: 내가 고친 날의 항목 ID는 다른 날에서 빼고, 최신 코스에 없는 ID는 지워 새 항목으로 보낸다.
- Rationale: 동행이 항목을 다른 날로 옮기거나 지웠을 때 PUT 본문이 같은 ID를 두 번 담거나 없는 ID를 담으면 서버가 거절한다.
