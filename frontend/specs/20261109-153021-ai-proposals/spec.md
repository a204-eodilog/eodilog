## Clarifications

### Session 2026-11-09

- Q: 변경안 API가 없는데? → A: API 명세대로 부르고 테스트 모드 가짜 서버가 장소 빼기(PLACE_REMOVED)와 날씨(WEATHER) 변경안, 적용, 되돌리기를 흉내 낸다. 실서버에서는 재계산 실패가 보인다 (가정 — 사용자 확인 필요, Q-11-1)
- Q: S24 [빼기]는 어떻게 들어오나? → A: S29를 장소와 함께 열고, S29가 PLACE_REMOVED 변경안 작업을 만든다. S26은 만든 작업 번호로 연다 (가정 — 사용자 확인 필요, Q-11-2)
- Q: 비교 숫자 칸의 '이동' 시간은? → A: 변경안 응답에는 구간 시간이 없다. 기존 코스 구간 시간은 보이고, 바뀐 쪽은 "계산 전"으로 둔다. 장소 수와 마지막 일정 시각은 비교한다 (가정 — 사용자 확인 필요, Q-11-3)
- Q: 적용 뒤 어디로? → A: 코스(S24)로 바꿔 가고 "새 코스를 적용했어요"와 [되돌리기]를 띄운다. 되돌리기는 이 알림에서 한 번만. 그 사이 코스가 바뀌었으면 409 UNDO_UNAVAILABLE 안내 (가정 — 사용자 확인 필요, Q-11-4)
- Q: 적용할 때 코스가 그 사이 바뀌었으면? → A: 오래된 변경안 화면은 만들지 않고 "그 사이 코스가 바뀌어 적용하지 못했어요"와 [다시 만들기]로 같은 요청을 새로 만든다 (가정 — 사용자 확인 필요, Q-11-5)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 변경안 비교하고 적용 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 변경안 작업이 끝났다, **Then** 위에 무엇이 바뀌는지("광안리 바다뷰 카페를 빼요", "1일차 2번째 장소"), 숫자 칸 셋(장소, 이동, 마지막 일정과 기존 값), 기준 수단과 계산 시각, 바뀐 날 지도와 목록. 목록 줄에 그대로·당겨짐·늦춰짐·새로 표시, 빠진 장소는 줄 긋고 '빠짐', 구간이 바뀌면 '바뀜'.
2. **When** [적용], **Then** 지금 코스가 바뀌고 S24로 가서 "새 코스를 적용했어요"와 [되돌리기]. 동행 누구나 적용한다.
3. **When** [적용 안 함], **Then** 코스는 그대로 두고 돌아간다.
4. **Given** 작업이 끝나기 전, **Then** "변경안을 만들고 있어요".

### User Story 2 - 되돌리기 (Priority: P1)

1. **When** 적용 직후 [되돌리기], **Then** 적용 전 코스로 돌아가고 "되돌렸어요".
2. **Given** 그 사이 코스가 바뀌었다, **When** [되돌리기], **Then** "그 사이 코스가 바뀌어 되돌릴 수 없어요".

### User Story 3 - 재계산 실패와 충돌 (Priority: P2)

1. **Given** 작업이 실패했다, **Then** "동선을 다시 짜지 못했어요", "이동 시간을 구하지 못했어요 / 지금 코스는 그대로예요", [다시 시도], [코스 보기].
2. **Given** 적용이 409, **Then** "그 사이 코스가 바뀌어 적용하지 못했어요"와 [다시 만들기].

### User Story 4 - 들어가기 (Priority: P2)

1. S24 장소의 [빼기] → S29가 그 장소를 뺀 변경안을 만든다.
2. S26 결과 시트의 [변경안 보기] → 그 변경안의 S29.

### Edge Cases

- 날씨 대안이 안내뿐이라 적용할 수 없으면(422 UNSCHEDULABLE_ALTERNATIVE) "이 대안은 코스에 넣을 수 없어요".
- 작업이 2분을 넘기면 재계산 실패와 같다.
- 바뀐 날이 없으면 첫째 날을 보인다.

## Requirements _(mandatory)_

- **FR-001**: 변경안 작업을 기다려 비교를 보여야 한다. 비교는 바뀐 날의 지금 코스와 제안 코스.
- **FR-002**: 무엇이 바뀌는지 한 줄, 숫자 칸 셋, 줄마다 바뀐 표시를 보여야 한다.
- **FR-003**: 승인 단계 없이 누구나 적용할 수 있어야 하고, 적용은 baseVersion으로 보낸다.
- **FR-004**: 적용 직후 한 번 되돌릴 수 있어야 하고, 409 UNDO_UNAVAILABLE을 안내해야 한다.
- **FR-005**: 적용 409는 안내와 다시 만들기로 처리하고 오래된 변경안 화면을 만들지 않는다.
- **FR-006**: 작업 실패는 재계산 실패 화면.
- **FR-007**: S24 [빼기]와 S26 [변경안 보기]에서 들어와야 한다.
- **FR-008**: 3개 상태와 생성 중을 미리보기에서 볼 수 있어야 한다.

## Success Criteria _(mandatory)_

- **SC-001**: 3개 상태를 미리보기에서 볼 수 있다.
- **SC-002**: [적용]을 빠르게 두 번 눌러도 적용 요청은 하나다.
- **SC-003**: 되돌리기 뒤 코스가 적용 전과 같다(가짜 서버 흐름으로 확인).

## Assumptions

- 변경안·적용·되돌리기 백엔드가 없다 (Q-11-1).
- 되돌리기는 적용 알림이 떠 있는 동안만 누를 수 있다.
