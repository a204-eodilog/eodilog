# Research: 여행·채팅 일상 문제 고치기

## R1. 자동 참여 뒤 "이동하는 중"에서 멈춤

- **원인**: `invite-screen.tsx`는 이미 동행이면 1.2초 뒤 참여 요청을 자동으로 보낸다. 요청이 실패하면 `onError`가 토스트만 띄우고, 화면은 `alreadyMember` 갈래의 "이동하는 중"을 계속 그린다. 이 갈래에는 머리글도 버튼도 없어 뒤로 갈 길이 없다. 자동 요청은 `autoJoined` 표시로 한 번만 보내므로 다시 시도도 없다.
- **Decision**: `alreadyMember` 갈래에서 `accept.isError`이고 초대 문제(무효·정원)가 아니면 기존 `Notice` 모양으로 "여행으로 이동하지 못했어요"와 [다시 시도], [홈으로]를 보인다. [다시 시도]는 참여 요청을 다시 보낸다.
- **Rationale**: 화면 구조를 바꾸지 않고 갈래 하나만 더한다. 다른 담당 화면이라 최소 변경이어야 한다.
- **Alternatives considered**: 실패하면 자동으로 여러 번 다시 시도 — 끊긴 동안 계속 도는 것은 이번에 없애려는 "멈춘 것처럼 보이는 화면"과 같다. 실패하면 바로 홈으로 — 왜 여행이 안 열렸는지 알 수 없다.

## R2. 빈 대화방이 새 메시지를 못 따라감

- **원인**: `chat-inbound.ts`의 이어 받기 `catchUp`은 "어디까지 받았나"(`syncedUpTo`)가 없으면 바로 끝난다. 메시지가 없는 창은 이 값이 없다. 마지막 메시지 확인 `checkLatest`도 `newestSequence === null`이면 건너뛴다. 그래서 처음 열 때 비어 있던 방은 앱을 내려 두었다 돌아오거나 실시간 알림을 놓치면, 방을 다시 열 때까지 아무것도 받지 않는다.
- **Decision**: 창은 있는데 메시지가 없으면 "처음 받기를 다시 하는 것"으로 다룬다. `catchUp`과 `checkLatest`가 최신 페이지를 받아 `hasOlder`와 함께 입구(`receive`)로 넣는다. 요청 수는 그대로다(이어 받기 1번, 확인 간격당 1번).
- **Rationale**: 순번 기준을 바꾸지 않아 메시지가 있는 방의 동작은 그대로다. 입구 하나로 넣으므로 중복 제거·내 말풍선 정리·목록 갱신이 같은 순서로 된다.
- **Alternatives considered**: 빈 창의 기준 순번을 0으로 보기 — 나중에 들어온 동행에게 서버가 이전 메시지를 주지 않는 경우, 채워지지 않는 빈칸을 메시지마다 다시 요청하게 된다.

## R3. 대화방이 두 번 열림

- **원인**: `chat-rooms-screen.tsx`의 `open`은 누를 때마다 `router.push`를 부른다. 화면이 바뀌기 전에 두 번째 누름이 들어오면 같은 화면이 두 겹으로 쌓인다.
- **Decision**: `src/hooks/use-open-once.ts`를 만든다. 한 번 부르면 잠그고, 이 화면이 다시 앞으로 올 때(`useFocusEffect`) 푼다. 화면 이동이 일어나지 않은 경우를 위해 1초 뒤에도 푼다. 잠긴 동안의 누름은 방이 달라도 받지 않는다(Q-13-3).
- **Rationale**: 목록 화면 쪽에서 막으면 대화방 화면이나 라우터 설정을 건드리지 않는다. 다른 목록도 같은 훅을 쓸 수 있다.
- **Alternatives considered**: `router.navigate`로 바꾸기 — 같은 화면이 이미 맨 위면 다시 열지 않지만, 첫 이동이 끝나기 전의 두 번째 누름은 여전히 쌓일 수 있고 다른 방을 누른 경우를 못 막는다. 누른 뒤 일정 시간 무시 — 느린 기기에서 시간이 모자라면 다시 열린다.

## R4. 여행 메뉴 네 개

- **지금 아는 것**: `trip-menu-grid.tsx`에서 코스·평가·경비는 화면 주소로 가고 게시만 준비 중 안내다. 왜 안 나왔는지는 눌러 봐야 안다.
- **Decision**: 테스트 모드 웹 미리보기에서 시험 데이터의 여행마다 네 메뉴를 눌러 `menu-check.md`에 표로 적는다. 열리지 않거나 빈 화면이면 콘솔·요청 기록으로 시험 데이터 문제인지 화면 코드 문제인지 가린다. 코스 화면과 시험 데이터는 고치고, 평가·경비 화면 코드는 원인만 적는다.
- **Rationale**: 추측으로 고치지 않는다. 휴대폰에서만 나는 문제는 사용자 확인 항목으로 넘긴다(Q-13-4).
