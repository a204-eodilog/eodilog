# Quickstart: 동행 초대·관리·나가기 확인

구현이 명세대로 되는지 확인하는 순서다. 코드와 응답 모양은 [contracts](./contracts/companions-api.md)와 [data-model](./data-model.md)을 본다.

## 준비

- **자동 검사**: `frontend/`에서 아래 세 개를 돌린다.

  ```bash
  npx tsc --noEmit
  ```

  ```bash
  npx expo lint
  ```

  ```bash
  npx jest
  ```

- **웹 테스트 모드**: `.claude/launch.json`의 `expo-web`으로 띄운다(`EXPO_PUBLIC_DEV_MOCK=true`). 가짜 응답이 버전을 올리고 409를 준다(research R15).
- **실서버**:
  1. `EodiLog/dev-up.cmd`로 로컬 백엔드를 켠다.
  2. `expo-web-live`(`EXPO_PUBLIC_DEV_MOCK=false`, `http://localhost:8080`)로 띄운다.
  3. 계정 두 개가 필요하다(방장 A, 동행 B). B는 A가 만든 링크의 토큰으로 `POST /invitations/{token}/accept`를 보내 참여시킨다. S04 화면은 A 담당이라 이 명세에서는 API로 넣는다.
- **기기**: 안드로이드 개발 빌드. 공유 창, 클립보드, 뒤로 가기 동작은 기기에서만 확인한다.

## 2. 여행 정보 수정 (US2)

| # | 할 일 | 기대 |
| --- | --- | --- |
| 2-1 | B(동행)가 설정 버튼 | S19 동행 화면. 메뉴는 '여행에서 나가기'만 있다(SC-004) |
| 2-2 | 기간·여행지가 없는 여행에 기간·여행지를 넣고 [완료] | 상세의 큰 제목·'지금 할 일'이 여행지 정해짐으로 바뀐다. 여행 탭과 N4 목록도 바뀐다 |
| 2-3 | 이름만 바꾸고 [완료] | PATCH 본문에 `title`·`expectedVersion`만 있다 |
| 2-4 | 아무것도 안 바꾸고 [완료] | 요청 없이 상세로 |
| 2-5 | A·B가 둘 다 S19를 열고, A가 먼저 저장한 뒤 B가 저장 | B는 409 안내와 A가 저장한 값을 본다. B의 값은 저장되지 않았다(SC-003) |
| 2-6 | 저장 중 연결 끊기(테스트 모드는 네트워크 끊기) | 빨간 띠 "여행 정보를 저장하지 못했어요". 입력값이 남아 있다 |

## 3. 나가기 (US3)

| # | 할 일 | 기대 |
| --- | --- | --- |
| 3-1 | B가 [여행에서 나가기] | 시트에 채팅 체크(꺼짐), "경비 기록은 남아요". 사진 줄은 없다 |
| 3-2 | 채팅 체크를 켜고 [나가기] | 202. 여행 탭으로 가고 그 여행은 목록에 없다. [나가기]를 누르고 목록이 보일 때까지 3초 안(SC-007) |
| 3-3 | 3-2 뒤 기기 뒤로 가기 | 나간 여행 상세나 설정으로 돌아가지 않는다 |
| 3-4 | A·B·C 여행에서 A(방장)가 나가기 | "나가면 B님이 방장이 돼요 · 다른 사람에게 넘기기". 나간 뒤 B의 S19가 방장 화면이다(SC-005) |
| 3-4b | A·B·C 여행에서 A가 나가기 시트의 [다른 사람에게 넘기기] → C 고르기 → 넘기기 | 나가기 시트가 동행용(이어받을 사람 안내 없음)으로 다시 열린다. [나가기]를 누르면 방장은 C이고 A의 목록에서 여행이 빠진다. 다시 열린 시트에서 [취소]하면 S19(동행 화면)에 남는다 |
| 3-5 | 3-4의 시트를 띄운 채로 다른 기기에서 B가 나간 뒤 A가 [나가기] | 409 안내. 시트가 "C님이 방장이 돼요"로 바뀐다 |
| 3-6 | 혼자 남은 여행에서 나가기 | "혼자 남아서 나가면 여행이 삭제돼요", [나가기]. 나간 뒤 `GET /trips/{id}`가 404 |
| 3-7 | 나간 여행의 상세 주소로 직접 들어가기 | "볼 수 없는 여행이에요" |

## 4. 방장 관리 (US4)

| # | 할 일 | 기대 |
| --- | --- | --- |
| 4-1 | A(방장) S19 | 방장 넘기기·동행 내보내기·여행에서 나가기·여행 삭제 |
| 4-2 | [방장 넘기기] → B 고르기 → [B님에게 넘기기] | 확인창 없이 넘어간다. S19가 동행 화면으로 바뀐다. S18 목록에서 B에 "방장" 표시가 있다 |
| 4-3 | 혼자인 방장 | 넘기기·내보내기를 누를 수 없고 이유가 보인다 |
| 4-4 | [동행 내보내기] → C → 확인 | C가 목록에서 빠진다. C 계정의 여행 목록에도 없다 |
| 4-5 | A가 방장 화면을 띄운 채 다른 기기에서 B에게 넘긴 뒤 A가 [동행 내보내기] | 403 → 다시 받기. "방장만 할 수 있어요"가 뜨고 방장 메뉴가 사라진다 |
| 4-6 | [여행 삭제] → 확인 | 202. 여행 탭으로 가고, B 계정에서도 목록에서 빠진다 |

## 팀에 알릴 것

MR 설명에 옮겨 적는다.

- **B(S50 시트)**:
  - `LeaveTripSheet`의 `cleanupSupported` 속성을 `showPhotos`(기본 false, 사진 줄 숨김)와 `messageCleanupSupported`(기본 true, 채팅 지우기 고르기)로 나눴다. 서버가 `deleteOwnMessages=true`를 이미 받기 때문이다.
  - 혼자 남았을 때 설명을 "{여행 이름}의 기록이 모두 지워져요. 되돌릴 수 없어요"로 바꿨다(동행 명세 FR-027). S50 문서 51행의 설명 문구와 다르다.
  - `docs/design/screens/S50-confirm.md` 9·51·65행은 B와 합의한 뒤 고친다.
- **피그마와 다르게 한 곳**:
  - S18에 [링크 취소] 글자 버튼을 [새 링크 만들기] 옆에 두었다. 피그마에는 자리가 없다.
  - 피그마 'S19 여행 정보 수정 · 저장 실패'는 동행 화면인데 [여행 삭제]가 있다. 명세 FR-016대로 동행에게는 보이지 않게 했다.
  - S19 구성원 얼굴 줄에는 방장 표시가 없고, 방장은 S18 목록에서 본다(명세 FR-019).
- **초대 링크 주소**: 서버가 주는 `ieohaeng://invitations/{token}` 앱 주소라 카카오톡에서 눌리는 링크로 보이지 않을 수 있다. 앱 이름·주소 변경(`eodilog`) 작업에서 다룬다.
- **N4 내 여행 목록**: 새 여행 만들기·수정·나가기 등 뒤에 `['me','trips']`도 새로 받게 했다(`invalidateTripLists`).
- **테스트 모드**: 웹 콘솔에서 `__devMock.bumpVersion('trip-1')`로 다른 동행의 변경(409)을, `__devMock.giveOwner('trip-1', 'member-1-2')`로 방장 바뀜(403)을 흉내 낼 수 있다. 내가 동행인 여행(`세은이 만든 여행`)과 정원이 찬 여행(`스무 명 워크숍`)을 더했다.
