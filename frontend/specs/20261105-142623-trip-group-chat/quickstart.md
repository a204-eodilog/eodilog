# Quickstart: 여행 그룹 채팅 확인

구현이 명세대로 되는지 확인하는 순서다. 응답 모양은 [contracts](./contracts/chat-api.md)를, 상태와 함수는 [data-model](./data-model.md)을 본다.

## 준비

- **자동 검사**: `frontend/`에서 아래 네 개를 돌린다.

  ```bash
  npx tsc --noEmit
  ```

  ```bash
  npx expo lint
  ```

  ```bash
  npx prettier --check src
  ```

  ```bash
  npx jest
  ```

- **서버 없이 상태 보기**: 개발 서버를 띄우고 `/dev/chats`를 연다. 아래 상태가 피그마와 같은 모양인지 본다.
  - S46: 기본, 대화방 없음, 연결 끊김
  - S47: 기본, 비참여자 차단, 시스템 메시지 모음, 투표, 코스, 보내는 중·실패
  - 피그마에 없는 상태(같은 화면의 토큰을 따른다):
    - S46: 로딩, 처음 불러오기 실패
    - S47: 로딩, 빈 대화방, 처음 불러오기 실패, 이전 메시지 불러오는 중·실패, "새 메시지" 버튼, 1,000자 초과 입력, 다시 보낼 수 없는 실패, 삭제된 메시지·나간 동행
- **웹 테스트 모드**: `.claude/launch.json`의 `expo-web`(`EXPO_PUBLIC_DEV_MOCK=true`)으로 띄운다. 실시간은 메모리 전달이다. `devMockControls.chat`으로 끊김, 다른 동행 메시지, 빈칸을 흉내 낸다.
- **실서버**:
  1. `EodiLog/dev-up.cmd`로 로컬 백엔드를 켠다.
  2. `expo-web-live`로 띄운다.
  3. 두 계정(A, B)이 같은 여행에 있어야 한다. 이전 명세 quickstart의 준비 방법을 쓴다.
  - 웹은 브라우저 WebSocket이라 RN 설정(이진 프레임)과 다르다. 연결 규칙만 여기서 확인하고, 마지막 확인은 기기에서 한다.
- **기기**: 안드로이드 개발 빌드. 먼저 `typeof TextDecoder`를 확인한다(research R2). 앱 앞뒤 전환, 비행기 모드, 스크롤 성능은 기기에서만 본다.

## 2. 실시간과 끊김 (US2)

| #   | 할 일                                                        | 기대                                                                                        |
| --- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 2-1 | A·B가 같은 방을 열고 B가 보내기                              | A 화면에 새로고침 없이 나타난다. 걸린 시간을 기록한다(SC-002)                               |
| 2-2 | A가 보내기                                                   | A 화면에 한 번만 보인다(201과 실시간이 둘 다 와도)                                          |
| 2-3 | A가 위로 올려 읽는 중에 B가 보내기                           | A의 읽던 자리가 그대로이고 "새 메시지" 버튼이 뜬다. 누르면 맨 아래로 간다                   |
| 2-4 | A 연결 끊기                                                  | 3초 뒤 S47 위에 끊김 안내가 뜬다. 1초 만에 되살리면 안내가 뜨지 않는다                      |
| 2-5 | A가 끊긴 동안 B가 7개 보낸 뒤 A 되살리기                     | 안내가 사라지고 7개가 순서대로 들어온다. 중복과 빠짐이 없다. 빈칸 채우기 요청 수를 기록한다 |
| 2-6 | A가 앱을 홈으로 보냈다가 1분 뒤 돌아오기(그동안 B가 보냄)    | 백그라운드 동안 끊김 안내가 없다. 돌아오면 다시 연결하고 놓친 메시지를 이어 받는다          |
| 2-7 | `skipNext()`로 실시간 하나를 빠뜨린 뒤 B가 두 개 보내기      | 두 번째가 오면 빈칸을 알아채고 빠진 것을 채워 순서대로 보인다                               |
| 2-8 | access 토큰 만료까지 기다리기(실서버, 만료 시간을 짧게 설정) | `ERROR UNAUTHENTICATED` 뒤 갱신하고 다시 연결한다. 사용자는 아무것도 하지 않는다            |
| 2-9 | refresh 토큰도 지운 뒤 2-8                                   | 다시 로그인 안내가 뜨고 연결을 멈춘다                                                       |

## 팀에 알릴 것

- **화면 목록 S46 "미확인 수"**: 넣지 않기로 했다(Clarifications 2026-11-05). `docs/flow/screen-list.md` S46 줄에서 지우자고 알린다.
- **시스템 메시지**: 서버가 SYSTEM 메시지를 만들 때 함께 정한다.
  - `target.type` 값(지금 앱은 `POLL`·`ITINERARY`를 쓴다)
  - 카드 문구 출처(지금 앱은 본문 첫 줄을 제목, 나머지를 설명으로 쓴다)
- **`src/realtime` 사용법**(투표·코스·알림 담당):
  - `realtime.subscribe(목적지, { onMessage, onResync })`로 붙는다. `onResync`는 구독이 끝날 때마다(처음 연결 포함) 불린다.
  - 목적지는 `src/realtime/destinations.ts`의 `ALLOWED_DESTINATIONS`에 서버 허용과 함께 더한다. 허용되지 않은 구독은 서버가 연결 전체를 닫는다.
  - `src/realtime`은 `features/*`를 불러오지 않는다. 등록은 `src/app/_layout.tsx`나 기능 코드에서 한다.
- **S47 주소**: `/trips/[tripId]/chat`. 시스템 카드 이동은 `src/features/chat/system-card-routes.ts` 표를 채우면 된다.
- **다른 담당 파일 수정**:
  - 평가 화면 이동 2곳(`trip-menu-grid.tsx`, `my-trip-record-screen.tsx`)을 문자열 주소로 바꿨다. `visits`가 폴더(index)로 바뀐 뒤 pathname 객체가 타입 검사를 깨서다.
  - `src/features/friends/api.test.ts`에 환경 설정 흉내를 더했다. jest가 `.env`를 읽지 않아 dev에서도 실패하던 테스트다.

## 구현 메모(2026-11-05)

- **웹 미리보기 FlashList**: 마지막 줄이 키 큰 시스템 카드일 때, 처음에는 마지막 한 줄만 그려지고 스크롤하면 나머지가 그려진다(`/dev/chats` 시스템 메시지 모음).
  - 맨 아래로 다시 맞추기(onLoad)로는 스크롤 이벤트가 생기지 않아 고쳐지지 않았다.
  - 기기에서도 생기는지 T068에서 확인한다. 서버가 아직 SYSTEM 메시지를 만들지 않아 지금 실제 대화에는 생기지 않는다.
- **키보드**: `react-native-keyboard-controller`는 설치돼 있지만 쓰지 않았다. RN `KeyboardAvoidingView`(`padding`)를 썼고, 안드로이드에서 입력 칸이 가려지지 않는지는 T068에서 확인한다.
- **앱 앞뒤 전환**: `inactive`에는 연결을 끊지 않는다(FR-018). `background`일 때만 끊는다.
- **파일 이름 차이**: 차단 정리는 `hooks/block-room.ts`(차단)와 `hooks/chat-forget.ts`(나가기·차단 공통)로 나눴다. 이어 받기·빈칸 채우기는 React 밖에서도 불러야 해서 처음엔 `catch-up.ts`에 두었다. 2026-11-06 동기화 엔진 구조로 바꾸며 메시지 입구 하나(`receive`)와 함께 `chat-inbound.ts`(받기 담당)로 옮겼고, 테스트는 `chat-inbound.test.ts`에 있다. 보내기·자동 재전송은 `hooks/use-send-message.ts`(보내기 담당), 보내는 중 메시지 기기 저장은 `hooks/outbox-storage.ts`(MMKV)다. 동시 전송·끊김 시뮬레이션은 `concurrent-send.sim.test.tsx`(약 1분).
