## Clarifications

### Session 2026-11-09

- Q: 제안 결과를 하나씩 고르는 단계가 있나, 바로 목록에 더하나? → A: 고르는 단계 없이 지금 목록에 없는 이름의 제안을 모두 바로 더한다. 디자인에 고르는 화면이 없고, 마음에 안 드는 항목은 더보기로 지우면 된다 (가정 — 사용자 확인 필요, Q-5-1)
- Q: 서버가 이유 종류를 주지 않는데 이유 줄 아이콘은? → A: 디자인의 날씨·걷기·시계 아이콘 대신 전구 아이콘 하나로 통일한다 (가정 — 사용자 확인 필요, Q-5-2)
- Q: 챙긴 사람 문구와 조사는? → A: 동행 이름 뒤에 받침이 있으면 '이', 없으면 '가'를 붙여 "세은이 챙겨요"·"민수가 챙겨요"로 쓴다. 나도 이름으로 쓴다. 한글로 끝나지 않으면 "Amy이(가) 챙겨요". 이유가 있으면 "오전 비 70% · 세은이 챙겨요"처럼 한 줄에 잇고, 이유가 없으면 이름 아래에 챙긴 사람만 쓴다 (가정 — 사용자 확인 필요, Q-5-3)
- Q: 디자인이 없는 빈 상태 [직접 추가] 동작과 고치기 시트 모양은? → A: [직접 추가]를 누르면 빈 상태 안내 아래에 '챙길 것 추가' 입력이 나타나고 초점이 간다. 고치기 시트는 아래에서 올라오는 시트로 제목 "준비물 고치기", 이름 입력, [저장], 빨간 글씨 [지우기]를 둔다. 지우기는 확인 없이 바로 지운다 (가정 — 사용자 확인 필요, Q-5-4)
- Q: S25 여행 중 화면이 없을 때 진입은? → A: S17 여행 상세 메뉴의 '여행 중'이 준비물 화면을 연다. 10번 주제에서 S25가 생기면 '여행 중'은 S25로 바꾸고 준비물은 S25 안에서 연다 (가정 — 사용자 확인 필요, Q-5-5)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 함께 쓰는 준비물 목록 보고 체크하기 (Priority: P1)

동행은 여행의 준비물 화면(S27)에서 동행 모두가 같이 쓰는 목록 하나를 본다. 항목마다 체크 상자, 이름, 왜 챙기는지(AI 제안 이유)가 보이고, 누가 챙겼는지도 보인다. 체크 상자를 눌러 챙김·해제를 바꾼다.

**Why this priority**: 이 화면의 존재 이유다. 목록을 보고 체크하는 것만으로도 여행 준비에 쓸모가 있다.

**Independent Test**: 동행 3명인 여행에 준비물 6개(체크 3개)를 둔다. 한 계정으로 S27을 열어 "6개 중 3개 챙겼어요"와 막대, 챙긴 사람 표시를 확인하고, 한 항목을 체크하면 "6개 중 4개"로 바뀌고 내 이름이 챙긴 사람으로 보이는지, 다른 계정으로 다시 열어도 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 준비물이 있는 여행, **When** S27을 열면, **Then** 머리에 뒤로, '준비물', 여행 이름, 동행 얼굴이 보이고 아래에 "6개 중 3개 챙겼어요"와 챙긴 비율만큼 찬 막대가 보인다(S27 기본, Figma 201-15314).
2. **Given** S27 기본, **When** 목록을 보면, **Then** 추가한 순서대로 항목마다 체크 상자와 이름이 보인다. 챙긴 항목은 체크 상자가 채워지고 이름이 흐리게 보인다.
3. **Given** AI 제안에서 온 항목, **When** 줄을 보면, **Then** 이름 아래에 전구 아이콘과 제안 이유("오전 비 70%")가 한 줄로 보인다 (가정 — 사용자 확인 필요, Q-5-2)
4. **Given** 누군가 챙긴 항목, **When** 줄을 보면, **Then** "오전 비 70% · 세은이 챙겨요"처럼 이유 뒤에, 이유가 없으면 이름 아래에 챙긴 동행 이름이 보인다. 이름 뒤 조사는 받침에 따라 이·가를 쓴다. 나간 동행이라 이름을 알 수 없으면 "동행이 챙겨요"로 보인다 (가정 — 사용자 확인 필요, Q-5-3)
5. **Given** 직접 추가한 항목, **When** 줄을 보면, **Then** 이름 옆에 '직접 추가' 표시가 보인다. AI 제안을 고친 항목은 '직접 고침' 표시가 보인다.
6. **Given** 챙기지 않은 항목, **When** 체크 상자를 누르면, **Then** 바로 챙긴 모습과 챙긴 사람(나)이 보이고 위쪽 진행 숫자와 막대가 바뀐다. 챙긴 항목을 누르면 해제되고 챙긴 사람 표시가 사라진다.
7. **Given** 체크 상자를 빠르게 여러 번 누른 경우, **When** 저장이 끝나면, **Then** 마지막으로 보이는 상태(챙김 또는 해제)가 서버에 남고 화면과 서버가 같다.
8. **Given** 다른 동행이 그 항목을 먼저 바꾼 경우, **When** 내가 체크를 바꾸면, **Then** 다른 동행의 변경을 덮어쓰지 않고 최신 목록을 다시 받아 보여 주며 "다른 동행이 먼저 바꿨어요. 최신 목록을 불러왔어요" 같은 안내를 띄운다.
9. **Given** 다른 동행이 그 항목을 지운 경우, **When** 내가 체크를 바꾸면, **Then** 그 항목을 목록에서 빼고 "이미 지워진 준비물이에요" 같은 안내를 띄운다.
10. **Given** 연결이 끊겨 저장에 실패한 경우, **When** 실패를 알게 되면, **Then** 체크 상태를 서버에 마지막으로 저장된 상태로 되돌리고 실패 안내를 띄운다.

### User Story 2 - 직접 추가·고치기·지우기 (Priority: P1)

동행은 목록 아래 '챙길 것 추가' 입력으로 준비물을 더하고, 항목 오른쪽 더보기로 고치기 시트를 열어 이름을 고치거나 지운다.

**Why this priority**: AI 제안이 없거나 꺼져 있어도 목록을 만들 수 있어야 한다. 빈 상태에서 바로 쓸 수 있는 유일한 길이다.

**Independent Test**: 빈 여행에서 S27을 열어 [직접 추가]로 "손난로"를 넣고, 더보기로 "손난로 2개"로 고친 뒤 지워서 다시 빈 상태가 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** S27 기본, **When** 아래 '챙길 것 추가' 입력에 이름을 쓰고 추가 버튼이나 키보드 완료를 누르면, **Then** 목록 맨 아래에 챙기지 않은 항목으로 더해지고 '직접 추가' 표시가 보이며 입력이 비워진다.
2. **Given** 입력이 비었거나 공백뿐인 경우, **When** 추가 버튼을 보면, **Then** 추가 버튼이 눌리지 않는다.
3. **Given** 앞뒤 공백을 뺀 이름이 255자를 넘는 경우, **When** 입력하면, **Then** 255자에서 더 써지지 않는다.
4. **Given** 추가를 누른 직후 저장이 끝나기 전, **When** 추가를 다시 누르면, **Then** 같은 항목이 두 번 더해지지 않는다.
5. **Given** 항목 줄, **When** 오른쪽 더보기를 누르면, **Then** 아래에서 "준비물 고치기" 시트가 올라오고 지금 이름이 채워진 입력, [저장], 빨간 글씨 [지우기]가 보인다 (가정 — 사용자 확인 필요, Q-5-4)
6. **Given** 고치기 시트, **When** 이름을 바꿔 [저장]을 누르면, **Then** 시트가 닫히고 줄의 이름이 바뀐다. AI 제안 항목이었으면 '직접 고침' 표시가 붙는다. 이름이 그대로면 저장해도 아무것도 바뀌지 않는다.
7. **Given** 고치기 시트, **When** [지우기]를 누르면, **Then** 확인 없이 시트가 닫히고 항목이 목록에서 빠지며 진행 숫자가 바뀐다 (가정 — 사용자 확인 필요, Q-5-4)
8. **Given** 고치기 시트에서 저장할 때 다른 동행이 먼저 바꾼 경우, **When** 저장에 실패하면, **Then** 덮어쓰지 않고 최신 목록을 다시 받아 안내한다. 시트는 닫는다.
9. **Given** 마지막 항목을 지운 경우, **When** 목록이 비면, **Then** 항목 없음 상태(User Story 3)로 바뀐다.

### User Story 3 - 비어 있을 때 시작하기 (Priority: P2)

준비물이 하나도 없는 여행에서 S27을 열면 빈 상태 안내와 함께 [제안 받기]와 [직접 추가]가 보인다.

**Why this priority**: 처음 들어온 동행이 무엇을 해야 할지 알려 준다. 기본 목록 화면이 있어야 의미가 있어 P2다.

**Independent Test**: 준비물이 없는 여행에서 S27을 열어 빈 상태를 보고, [직접 추가]를 누르면 입력에 바로 쓸 수 있는지, [제안 받기]를 누르면 제안이 진행되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 준비물이 없는 여행, **When** S27을 열면, **Then** 가방 그림, "준비물이 없어요", "날씨·일정 기준 준비물" 설명, [제안 받기], [직접 추가]가 보인다(S27 항목 없음, Figma 201-15518).
2. **Given** S27 항목 없음, **When** [직접 추가]를 누르면, **Then** 빈 상태 안내 아래에 '챙길 것 추가' 입력이 나타나고 바로 쓸 수 있게 초점이 간다. 첫 항목을 더하면 기본 상태로 바뀐다 (가정 — 사용자 확인 필요, Q-5-4)
3. **Given** S27 항목 없음, **When** [제안 받기]를 누르면, **Then** User Story 4와 같은 제안 받기가 시작된다.

### User Story 4 - 다시 제안 받기 (Priority: P2)

동행은 맨 아래 [다시 제안 받기]로 여행 기간·코스·날씨 기준 AI 준비물 제안을 받는다. 제안은 지금 목록에 더해지고, 직접 고친 항목이나 지운 항목은 그대로다.

**Why this priority**: 체크리스트를 빠르게 채워 주는 기능이지만, 없어도 목록은 쓸 수 있다.

**Independent Test**: 직접 고친 항목 하나와 지운 항목 하나가 있는 여행에서 [다시 제안 받기]를 누르고, 끝난 뒤 고친 항목 이름이 그대로이고 지운 항목이 돌아오지 않았으며 새 제안만 더해졌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** S27 기본, **When** [다시 제안 받기]를 누르면, **Then** 버튼이 "제안 받는 중…"으로 바뀌어 다시 눌리지 않고, 제안 작업이 끝날 때까지 기다린다.
2. **Given** 제안 작업이 끝난 경우, **When** 결과가 오면, **Then** 고르는 단계 없이 지금 목록에 없는 이름의 제안이 모두 챙기지 않은 항목으로 목록 아래에 더해지고 각 항목에 제안 이유가 보인다. "준비물 3개를 더했어요" 같은 안내가 뜬다. 더할 것이 없으면 "새로 더할 준비물이 없어요"가 뜬다 (가정 — 사용자 확인 필요, Q-5-1)
3. **Given** 직접 고친 항목이나 이미 있는 항목, **When** 제안이 더해지면, **Then** 그 항목들의 이름·체크·챙긴 사람은 바뀌지 않는다.
4. **Given** 동행이 지운 항목, **When** 제안이 더해지면, **Then** 지운 항목은 다시 생기지 않는다.
5. **Given** 응답을 놓쳐 [다시 제안 받기]가 다시 보내진 경우, **When** 같은 요청이 두 번 가면, **Then** 제안 작업은 하나만 생긴다.
6. **Given** 같은 제안을 다른 동행이 먼저 더한 경우, **When** 내가 그 제안을 더하려 하면, **Then** 그 제안은 건너뛰고 나머지를 더한 뒤 최신 목록을 다시 받는다.
7. **Given** 제안 작업이 실패하거나 취소되거나 너무 오래 걸린 경우, **When** 실패를 알게 되면, **Then** 목록은 그대로 두고 위쪽에 "준비물을 다시 제안하지 못했어요 · 지금 목록은 그대로예요" 카드와 [다시 시도]를 보인다(S27 다시 제안 실패, Figma 201-30067). 아래 버튼 옆에 "직접 고친 항목은 그대로 둬요" 안내가 보인다.
8. **Given** 다시 제안 실패 카드, **When** [다시 시도]를 누르면, **Then** 카드가 사라지고 새 제안 요청을 보낸다.
9. **Given** 내 준비물 추천 설정이 꺼진 경우, **When** 제안을 받으려 하면, **Then** 실패 카드에 "준비물 추천이 꺼져 있어요 · 설정에서 켜면 제안을 받을 수 있어요"와 [설정 열기]를 보인다.

### User Story 5 - 화면 들어가기 (Priority: P3)

동행은 여행 상세(S17)에서 준비물 화면으로 간다. 본래 길은 여행 중 화면(S25)의 준비물 진입이지만 S25는 아직 없다.

**Why this priority**: 진입이 없으면 화면을 쓸 수 없지만 임시 연결이라 P3다.

**Independent Test**: S17에서 '여행 중' 메뉴를 눌러 S27이 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** S17 여행 상세, **When** '여행 중' 메뉴를 누르면, **Then** 그 여행의 S27이 열린다. 여행 중 화면(S25)이 생기면 '여행 중'은 S25로 바꾸고 준비물은 S25 안에서 연다 (가정 — 사용자 확인 필요, Q-5-5)
2. **Given** 볼 수 없는 여행이나 없는 여행, **When** S27 주소를 열면, **Then** "여행을 찾을 수 없어요" 안내와 돌아가기가 보인다.

---

### Edge Cases

- 목록을 불러오지 못하면 오류 안내와 [다시 시도]가 보인다. 목록이 이미 있는 상태에서 다시 받다 실패하면 보이던 목록을 그대로 둔다.
- 체크한 동행이 여행에서 나가 멤버 목록에 없으면 "동행이 챙겨요"로 보인다.
- 이름이 길면 줄을 바꿔 다 보이고 더보기 버튼은 오른쪽에 그대로 있다.
- 제안 이유가 비어 있으면 이유 줄을 숨긴다.
- 제안 결과에 같은 이름이 두 번 있거나 지금 목록과 이름이 같으면(앞뒤 공백 빼고 대소문자 구분 없이) 한 번도 더하지 않는다.
- 제안을 기다리는 중 화면을 나가면 기다림을 멈춘다. 다시 들어와도 그 작업의 결과를 이어서 더하지 않는다.
- 제안 하나를 더하다 실패해도(다른 동행이 먼저 더함 등) 나머지는 계속 더한다.
- 고치기 시트를 연 사이 그 항목이 지워졌으면 저장·지우기 때 "이미 지워진 준비물이에요"를 띄우고 목록에서 뺀다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 여행마다 동행 모두가 같은 준비물 목록 하나를 보고, 추가한 순서대로 전부 보여야 한다.
- **FR-002**: 머리에 '준비물', 여행 이름, 참여 중인 동행 얼굴(나는 구분 색)이 보여야 한다.
- **FR-003**: "N개 중 M개 챙겼어요"와 M/N 비율의 막대가 보여야 한다.
- **FR-004**: 항목 줄은 체크 상자, 이름(챙긴 항목은 흐리게), AI 제안 이유 한 줄, 챙긴 동행 이름, 출처 표시('직접 추가'·'직접 고침'), 더보기 버튼을 보여야 한다.
- **FR-005**: 동행 누구나 체크·해제할 수 있고, 화면은 누르는 즉시 바뀌어야 한다. 챙긴 사람은 서버가 기록한 동행으로만 보인다.
- **FR-006**: 같은 항목의 체크를 빠르게 여러 번 바꾸면 마지막 상태가 서버에 남아야 하며, 한 항목에 동시에 두 개 넘는 저장 요청을 보내지 않아야 한다.
- **FR-007**: 다른 동행이 먼저 바꾼 항목을 덮어쓰지 않아야 한다. 충돌이 나면 최신 목록을 다시 받고 안내해야 한다. 지워진 항목이면 목록에서 빼고 안내해야 한다.
- **FR-008**: 동행 누구나 이름 1~255자(앞뒤 공백 제외)로 준비물을 추가할 수 있어야 하고, 한 번 누른 추가가 두 번 저장되지 않아야 한다.
- **FR-009**: 더보기로 여는 고치기 시트에서 이름을 고치거나 지울 수 있어야 한다.
- **FR-010**: 목록이 비면 항목 없음 상태와 [제안 받기]·[직접 추가]를 보여야 한다.
- **FR-011**: [다시 제안 받기]·[제안 받기]는 AI 제안 작업을 하나 요청하고 끝날 때까지 기다린 뒤, 고르는 단계 없이 지금 목록에 없는 이름의 제안을 모두 목록에 더해야 한다 (가정 — 사용자 확인 필요, Q-5-1) 응답을 놓쳐 다시 보내도 작업은 하나여야 한다.
- **FR-012**: 제안을 더할 때 기존 항목(직접 고친 항목 포함)은 바꾸지 않고, 지운 항목을 되살리지 않아야 한다.
- **FR-013**: 제안 작업이 실패·취소·시간 초과되면 목록을 그대로 두고 실패 카드와 [다시 시도]를 보여야 한다. 추천 설정이 꺼져 있으면 설정을 켜라는 안내와 [설정 열기]를 보여야 한다.
- **FR-014**: 제안을 받는 동안 버튼은 진행 중으로 보이고 다시 눌리지 않아야 한다.
- **FR-015**: S17의 '여행 중' 메뉴가 S27을 열어야 한다. S25가 생길 때까지 임시다 (가정 — 사용자 확인 필요, Q-5-5)
- **FR-016**: 기본, 항목 없음, 다시 제안 실패, 고치기 시트, 불러오기 실패, 제안 받는 중을 서버 없이 미리보기 화면에서 볼 수 있어야 한다.
- **FR-017**: 화면의 모든 안내 문구는 한국어여야 한다.

### Key Entities

- **준비물 항목**: 이름, 챙김 여부, 챙긴 동행, 챙긴 시각, 출처(직접·AI), 제안 이유, 직접 고쳤는지, 수정 기준 번호(버전). 여행 하나에 목록 하나.
- **준비물 제안 작업**: 요청한 동행, 상태(대기·진행·성공·실패·취소), 결과 제안 목록(이름, 이유). 제안은 목록 안 순번으로 가리킨다.
- **동행**: 이름과 얼굴. 챙긴 사람 이름을 찾는 데 쓴다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 기본, 항목 없음, 다시 제안 실패, 고치기 시트를 포함한 6개 화면 상태를 서버 없이 미리보기에서 모두 볼 수 있다.
- **SC-002**: 한 항목의 체크를 1초 안에 5번 눌러도 저장 요청은 3번 이하이고, 끝난 뒤 화면과 서버 상태가 같다.
- **SC-003**: 다시 제안을 받은 뒤 직접 고친 항목의 이름·체크와 지운 항목의 부재가 100% 그대로다.
- **SC-004**: 체크 상자를 누르면 0.1초 안에 화면이 바뀐다(저장을 기다리지 않는다).
- **SC-005**: 추가 버튼을 빠르게 두 번 눌러도 항목은 하나만 생긴다.

## Assumptions

- 백엔드가 이미 준비물 조회·추가·수정·삭제, 제안 요청, 작업 조회를 제공한다. 이번 주제는 화면만 만든다.
- 제안 결과에는 이유만 있고 이유 종류(날씨·걷기·시간)가 없으므로 이유 줄의 아이콘은 전구 하나로 통일한다 (가정 — 사용자 확인 필요, Q-5-2)
- 챙긴 사람은 여행 상세의 참여 중인 동행 목록에서 이름을 찾는다.
- 실시간 갱신은 이번 범위가 아니므로 다른 동행의 변경은 화면을 다시 열거나 충돌 때 다시 받아 반영한다.
- 제안 작업 기다림은 일정 간격으로 상태를 묻고, 2분이 넘으면 실패로 본다.
