## Clarifications

### Session 2026-11-09

- Q: 백엔드에 추천 API가 없는데 어떻게 만드나? → A: API 명세의 POST·GET과 RecommendationResult 형식 그대로 부르고, 테스트 모드 가짜 서버가 그룹 즐겨찾기로 결과를 만든다. 실서버에서는 생성 실패가 보인다 (가정 — 사용자 확인 필요, Q-9-1)
- Q: [투표 후보로]는 어디로 가나? → A: 투표 열기 시트(N8)는 투표 브랜치에만 있어 이 브랜치에서는 '준비 중이에요'다. 합칠 때 여행지는 지역 투표, 맛집·스팟은 장소 투표 후보로 그 항목을 넘겨 연다 (가정 — 사용자 확인 필요, Q-9-2)
- Q: 카드의 '반영한 취향' 얼굴 칩과 사진은? → A: 응답에 사람별 취향과 사진이 없어 빼고, 추천 이유 한 줄과 사진 자리 아이콘만 둔다 (가정 — 사용자 확인 필요, Q-9-3)
- Q: '겹침 없음'은 어떻게 알고, 사람별 묶음은? → A: 그룹 즐겨찾기의 겹친 곳 수가 0이면 위에 "함께 담은 장소가 아직 없어요" 카드를 보인다. 응답에 사람별 묶음이 없어 결과는 한 목록으로 보인다 (가정 — 사용자 확인 필요, Q-9-4)
- Q: 자료 부족 기준과 문구는? → A: 판정은 서버의 insufficientData를 따른다. 문구의 "3곳부터", "2명부터"는 디자인 값을 쓰고 지금 수는 응답 basis에서 가져온다 (가정 — 사용자 확인 필요, Q-9-5)
- Q: 취향을 입력하지 않았으면? → A: 내 취향이 하나도 없으면 추천 전에 취향 입력(S03, 추천 직전)으로 보낸다. 돌아오면 추천을 시작한다. [나중에]로 건너뛰어도 추천은 시작한다 (가정 — 사용자 확인 필요, Q-9-6)

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 추천 받고 결과 보기 (Priority: P1)

동행이 그룹 즐겨찾기나 여행 상세에서 추천을 열면 추천을 만드는 동안 단계가 보이고, 끝나면 이번 추천에 쓴 것과 여행지·맛집과 스팟 카드가 보인다.

**Independent Test**: 테스트 모드에서 S20 [추천 받기] → 생성 중 → 여행지 2곳, 맛집과 스팟 3곳.

**Acceptance Scenarios**:

1. **Given** 추천을 열면, **Then** "추천을 만들고 있어요", "보통 10초 안에 끝나요"와 세 단계(모은 장소 N곳 살펴보기, 취향 맞춰 보기, 여행지와 장소 고르기)가 시간에 따라 넘어간다.
2. **Given** 성공, **Then** 위에 "여행지 N", "맛집과 스팟 N" 칩, "이번 추천에 쓴 것"(모은 장소 N곳 · 겹침 N, 공개 취향 N명, 여행지와 기간), "개인 즐겨찾기와 비공개 취향은 쓰지 않았어요"가 보인다.
3. **Given** 성공, **Then** 여행지 카드는 이름, 지역, 추천 이유, [투표 후보로]. 맛집과 스팟 카드는 이름, 주소, 이유, [담기].
4. **Given** 칩을 누르면, **Then** 그 묶음으로 스크롤한다.

---

### User Story 2 - 결과로 다음 행동 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 맛집·스팟 카드, **When** [담기], **Then** 그룹 즐겨찾기에 내 이름으로 담기고 버튼이 '담김'으로 바뀐다. 이미 내가 담은 곳은 처음부터 '담김'.
2. **Given** 여행지 카드, **When** [투표 후보로], **Then** 지금은 '준비 중이에요' (Q-9-2).
3. **Given** 결과, **When** [재추천], **Then** 새 추천을 만든다.

---

### User Story 3 - 추천할 수 없을 때 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** 서버가 자료 부족이라고 답하면, **Then** "추천하기엔 아직 부족해요", "모은 장소 N곳 · 3곳부터 추천해요", "취향 고른 사람 N명 · 2명부터 추천해요", [장소 더 모으기] → S20, [취향 입력] → S03.
2. **Given** 작업이 실패하거나 2분이 넘으면, **Then** "추천을 만들지 못했어요", "모은 장소는 그대로예요", [다시 시도].
3. **Given** 겹친 곳이 0이면, **Then** 결과 위에 "함께 담은 장소가 아직 없어요", "그래서 한 사람의 취향을 따로 반영했어요" 카드.

---

### User Story 4 - 들어가기 (Priority: P3)

1. S20 [추천 받기]와 장소 없음의 [추천 받기], S17 '추천' 메뉴가 S21을 연다.
2. 내 취향이 비어 있으면 먼저 S03(추천 직전)으로 가고, 돌아오면 추천을 시작한다.

### Edge Cases

- 추천을 만드는 중 화면을 나가면 기다리기를 멈춘다.
- [담기]를 두 번 빨리 눌러도 한 번만 담긴다(그룹 즐겨찾기 담기 규칙).
- 결과에 장소나 지역이 비어 있는 항목은 보이지 않는다.
- 여행지가 없으면 기본 정보 칸에 "여행지 미정".

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 추천 작업을 요청하고 끝날 때까지 1.5초마다 확인하며, 2분이 넘으면 실패로 보여야 한다.
- **FR-002**: 생성 중 세 단계를 흐른 시간에 따라 보여야 한다(서버가 단계를 주지 않는다).
- **FR-003**: 결과를 여행지(REGION)와 맛집과 스팟(PLACE)으로 나눠 보이고 칩으로 이동할 수 있어야 한다.
- **FR-004**: 이번 추천에 쓴 것을 basis와 여행 정보로 보이고, 비공개 정보는 쓰지 않았다고 알려야 한다.
- **FR-005**: 맛집과 스팟을 그룹 즐겨찾기에 담을 수 있어야 한다. 담은 뒤 같은 캐시를 갱신한다.
- **FR-006**: 자료 부족, 겹침 없음, 실패 상태를 보여야 한다.
- **FR-007**: 재추천으로 새 작업을 만들 수 있어야 한다.
- **FR-008**: S20과 S17에서 들어올 수 있어야 하고, 취향이 비었으면 S03을 먼저 거쳐야 한다.
- **FR-009**: 5개 상태를 서버 없이 미리보기에서 볼 수 있어야 한다.

### Key Entities

- **추천 작업**: 요청, 상태, 결과.
- **추천 결과**: 항목들(종류, 지역 또는 장소, 이유), 근거(모은 장소 수, 반영한 사람 수), 자료 부족 여부.

## Success Criteria _(mandatory)_

- **SC-001**: 5개 상태를 미리보기에서 모두 볼 수 있다.
- **SC-002**: [담기]를 빠르게 두 번 눌러도 저장 요청은 하나다.
- **SC-003**: 화면을 나간 뒤에는 추천 확인 요청이 더 가지 않는다.

## Assumptions

- 추천 백엔드가 없다 (Q-9-1). 실서버에서는 생성 실패 화면이 보인다.
- 지역 이름은 응답의 Region.name, 장소 주소는 Place.address를 쓴다.
- POST 본문의 regionId는 보내지 않는다. 여행지 전체로 추천한다.
