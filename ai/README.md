## 2. AI 역할 요약

어디로그의 AI는 허용된 여행 데이터를 바탕으로 다음 작업을 수행한다.

1. 링크와 캡처에서 장소 후보를 식별한다.
2. 그룹원의 저장 장소와 취향을 종합해 여행지·맛집·스팟을 추천한다.
3. 실제 날씨와 일정에 근거해 대체 활동과 준비물을 제안한다.
4. 여행 사진을 주제별로 분류하고 비슷한 사진을 묶는다.
5. 추천·추출·분류의 근거와 처리 상태를 사용자가 이해할 수 있게 제공한다.

AI는 사실 데이터를 임의로 생성하거나 사용자의 확정 데이터를 자동으로 덮어쓰는 역할을 맡지 않는다.

## 3. 기능별 정의

### 3.1 링크·캡처 장소 식별

PRD 근거: `WD-FR-05`

사용자가 장소 URL이나 화면 캡처를 등록하면 장소 정보를 추출하고 지도에 표시할 후보를 반환한다.

#### 입력

- 사용자가 등록한 장소 URL
- 사용자가 등록한 화면 캡처
- 캡처에서 추출한 문자와 이미지 정보
- 지원 가능한 경우 URL의 공개 메타데이터

#### 출력

- 식별된 장소 후보 목록
- 후보별 장소명과 식별 근거
- 후보별 신뢰 수준
- 처리 결과 상태

#### 처리 상태

- `SUCCESS`: 장소 하나를 식별함
- `MULTIPLE_CANDIDATES`: 여러 장소 후보가 있음
- `NOT_FOUND`: 장소를 식별하지 못함
- `FAILED`: 처리 과정에서 오류가 발생함

#### 필수 동작

- 사용자가 결과를 확인한 뒤 장소를 확정한다.
- 잘못 식별된 장소를 수정하거나 제거할 수 있다.
- 식별하지 못하면 사용자가 장소를 직접 검색·지정할 수 있다.
- 근거가 부족한 경우 임의의 좌표를 확정하지 않는다.
- 한 자료에서 여러 장소가 발견될 가능성을 고려한다.

#### 기술 검증 대상

- URL 메타데이터 해석 범위
- OCR 정확도
- 이미지 기반 장소 식별 가능 범위
- 지도·장소 검색 결과와 후보를 연결하는 방식
- 지원할 사이트와 이미지 형식

### 3.2 그룹 취향·겹침 기반 추천

PRD 근거: `WD-FR-08`, `WD-FR-09`

그룹 구성원이 함께 저장한 장소와 각자가 공유를 허용한 취향을 종합해 여행지·맛집·스팟 후보를 추천한다.

#### 입력

- 그룹 즐겨찾기 장소
- 동일하거나 유사한 장소를 여러 명이 저장한 정보
- 사용자가 직접 입력한 취향
- 사용자가 활용을 허용한 행동 기반 취향
- 여행 지역, 날짜, 인원 등 여행 조건

#### 출력

- 추천 장소 목록
- 추천 장소별 추천 이유
- 추천에 반영한 입력 범위
- 그룹 공통 요소와 개인별 취향 요소의 구분
- 자료 부족·겹침 없음·처리 실패 상태

#### 필수 동작

- 여러 명이 같은 장소를 저장했다면 겹침으로 식별한다.
- 저장 장소가 겹치지 않으면 겹침이 있다고 꾸미지 않는다.
- 한 사람의 저장이나 취향을 그룹 전체의 합의처럼 표현하지 않는다.
- 직접 입력한 취향과 행동에서 추론한 취향을 구분한다.
- 추천 결과에 공개 가능한 이유를 제공한다.
- 사용자가 허용하지 않은 개인 보관함과 취향은 사용하거나 노출하지 않는다.

#### 대표 검증 사례

| 상황 | 기대 결과 |
|---|---|
| 두 사용자가 같은 카페를 저장하고 서로 다른 취향을 가짐 | 공통 저장을 식별하고 각자의 취향이 어떻게 반영됐는지 설명 |
| 그룹원의 저장 장소가 전혀 겹치지 않음 | 겹침이 없음을 알리고 개인별 허용 취향을 근거로 후보 제시 |
| 그룹원이 비공개 장소와 취향을 보유함 | 비공개 데이터의 내용이나 존재를 추천 이유에 노출하지 않음 |
| 추천할 데이터가 부족함 | 임의로 추천 근거를 만들지 않고 자료 부족 상태 제공 |

### 3.3 좋아요 기반 추천

PRD 근거: `WD-FR-10`, `WD-FR-31`

사용자가 공개된 장소나 여행 기록에 남긴 좋아요를 추천 신호로 활용한다.

#### 필수 동작

- 좋아요와 실제 방문 기록을 구분한다.
- 좋아요를 장소 평점으로 계산하지 않는다.
- 같은 요청이 반복돼도 좋아요 수가 중복 증가하지 않아야 한다.
- 좋아요 취소 이후 신규 추천에 반영할 정책을 적용한다.
- 비공개 여행의 위치, 사진, 반응한 사람을 다른 사용자에게 노출하지 않는다.

좋아요 대상, 신호 가중치, 취소 데이터의 반영 시점은 제품 정책 확정 후 적용한다.

---

### 3.4 최근 트렌드 여행지 추천

PRD 근거: `WD-FR-11`

합의된 기간에 충분한 공개 반응을 받은 여행지를 최근 트렌드 후보로 제공한다.

#### 입력 후보

- 공개된 장소 평가
- 공개된 좋아요
- 합의된 기간의 반응 수
- 사용을 허용한 취향·연령 정보

#### 필수 동작

- 기준 기간과 데이터 갱신 시점을 표시한다.
- 좋아요, 평가, 실제 방문을 서로 다른 신호로 다룬다.
- 표본이 부족하면 최근 인기 장소라고 단정하지 않는다.
- 개인화 추천과 전체 트렌드를 구분한다.
- 비공개 자료를 트렌드 집계나 추천 이유에 노출하지 않는다.

트렌드 최소 표본, 신호별 가중치, 연령 활용 여부는 별도 결정이 필요하다.

### 3.5 친구 추천

PRD 근거: `WD-FR-03`

사용자가 관계를 맺을 수 있는 친구 후보와 공개 가능한 추천 이유를 제공한다.

친구 추천은 개발 범위에 포함되지만 반드시 생성형 AI로 구현할 필요는 없다. 초기에는 공개된 정보와 명시적 관계를 이용한 규칙 기반 후보 생성도 가능하다.

#### 필수 동작

- 추천받았다는 이유로 자동으로 친구 관계를 만들지 않는다.
- 비공개 여행지, 연령, 관계 정보를 추천 이유에 노출하지 않는다.
- 추천 후보가 없을 때 빈 상태를 제공한다.
- 거절·숨김·중복 추천 정책을 반영할 수 있어야 한다.

---

### 3.6 날씨 대안 추천

PRD 근거: `WD-FR-16`

여행 날짜·장소·일정과 외부 서비스에서 조회한 실제 날씨 정보를 바탕으로 날씨 영향을 설명하고 대체 장소나 활동을 제안한다.

#### 입력

- 여행 날짜와 시간
- 확정 또는 작성 중인 코스
- 확인된 장소 정보
- 조회 시점이 포함된 날씨 데이터
- 확인 가능한 경우 장소 운영 정보

#### 출력

- 날씨가 일정에 미치는 영향
- 대체 장소 또는 활동 후보
- 대안을 추천한 이유
- 사용한 날씨 정보의 조회 시점
- 외부 정보 조회 실패 또는 데이터 부족 상태

#### 필수 동작

- 조회하지 않은 날씨와 영업 정보를 사실처럼 생성하지 않는다.
- 실제 데이터, 모델의 해석, 사용자의 입력을 구분한다.
- 대안 추천과 실제 코스 변경을 별도 행동으로 처리한다.
- 날씨 데이터가 오래됐거나 조회에 실패하면 이를 표시한다.

### 3.7 준비물 체크리스트 제안

PRD 근거: `WD-FR-17`

여행 일정, 장소, 날씨 정보를 바탕으로 준비물 체크리스트의 초안을 제안한다.

#### 필수 동작

- 사용자가 항목을 추가·수정·삭제할 수 있다.
- 준비 완료 여부를 체크하고 상태를 유지할 수 있다.
- 재추천 시 사용자가 수정하거나 체크한 항목을 임의로 덮어쓰지 않는다.
- 새 제안과 기존 사용자 항목을 구분한다.

개인 체크리스트와 그룹 공동 체크리스트의 범위와 편집 권한은 별도 결정이 필요하다.

### 3.8 사진 주제 분류·유사 사진 묶기

PRD 근거: `WD-FR-19`, `WD-FR-20`

여행에 등록한 사진을 주제별로 분류하고 시각적으로 비슷한 사진을 묶어 탐색을 돕는다.

#### 입력

- 업로드된 사진
- 사용 가능한 촬영 시각과 위치 정보
- 사진이 연결된 여행과 장소 정보

#### 출력

- 사진별 주제 분류 결과
- 유사 사진 그룹
- 분류·묶음 처리 상태
- 사용자가 보정할 수 있는 결과 식별자

#### 필수 동작

- 분류 결과와 원본 사진을 구분한다.
- 사용자가 잘못된 분류를 수정할 수 있다.
- 사용자가 잘못 묶인 사진을 분리할 수 있다.
- 촬영 정보가 없어도 업로드 자체를 실패 처리하지 않는다.
- 일부 사진 처리 실패 시 성공한 사진과 원본을 보존한다.
- 유사하다는 이유로 원본을 자동 삭제하지 않는다.

#### 현재 범위에서 제외

- 베스트 컷 자동 선정
- 하이라이트 영상 생성
- 원본 사진 자동 삭제

## 4. 자동화 기능과 AI의 경계

다음 기능은 자동으로 동작하지만 생성형 AI의 책임으로 두지 않는다.

| 기능 | 담당 방식 | 이유 |
|---|---|---|
| 장소 좌표·상세 정보 | 지도·장소 API | 확인 가능한 실제 데이터가 필요함 |
| 이동 시간·경로 | 경로 API | 교통수단과 조회 시점에 따른 정확한 계산이 필요함 |
| 일정 재조정 | 경로 최적화 로직 | 제약 조건과 확정 코스를 보존하는 결정론적 처리가 필요함 |
| 날씨 | 날씨 API | 최신성과 조회 시점이 필요한 사실 데이터임 |
| 영업시간·편의시설 | 장소·시설 API | 확인되지 않은 정보를 생성하면 안 됨 |
| 투표·그룹 관리 | 백엔드 비즈니스 로직 | 권한과 상태 일관성이 중요함 |
| 경비 계산·정산 | 계산 로직 | 같은 입력에 항상 같은 결과가 필요함 |
| 지도·타임라인·여행 요약 카드 | 데이터 집계 | 저장된 원천 자료를 정확히 반영해야 함 |
| 채팅·공개 범위 | 권한 시스템 | 메시지와 개인정보 접근을 통제해야 함 |

### 코스 추천·재조정

- AI 또는 추천 로직이 코스 초안을 제안할 수 있다.
- 추천안과 사용자가 확정한 코스는 별도 상태로 관리한다.
- 장소가 제외되면 남은 순서와 이동 시간을 다시 계산한다.
- 재계산에 실패해도 기존 확정 코스를 삭제하지 않는다.
- 변경된 항목과 이유를 사용자가 확인할 수 있어야 한다.
- 재조정 결과를 즉시 반영할지 승인 후 반영할지는 제품 정책으로 결정한다.

## 5. 공통 처리 원칙

### 5.1 설명 가능성

- 추천에는 공개 가능한 추천 이유를 제공한다.
- 어떤 범주의 입력을 반영했는지 사용자에게 알린다.
- 사용자 입력과 시스템이 추론한 정보를 구분한다.
- 자료 부족, 후보 없음, 처리 실패를 정상 결과와 구분한다.

### 5.2 사용자 제어

- 장소 식별, 추천, 사진 분류 결과를 사용자가 수정하거나 거절할 수 있어야 한다.
- 재요청과 재처리를 지원하되 기존 확정 결과를 임의로 삭제하지 않는다.
- 사용자 수정 결과를 이후 처리에서 존중한다.

### 5.3 개인정보와 권한

- 사용자가 추천 활용을 허용한 정보만 입력으로 사용한다.
- 개인 즐겨찾기, 비공개 취향, 비공개 사진·위치·경비·관계 정보를 다른 사용자에게 노출하지 않는다.
- 채팅 내용은 추천이나 피드 생성에 자동으로 사용하지 않는다.
- 사진 메타데이터와 캡처 속 개인정보는 필요한 항목만 처리한다.
- 외부 모델로 전송하는 데이터 범위와 보존 정책을 명시한다.
- 공개 철회·삭제·탈퇴 시 추천과 파생 결과의 접근 권한도 갱신한다.

### 5.4 사실성

- 실제 장소, 좌표, 날씨, 영업시간, 이동 시간은 검증된 데이터만 사용한다.
- 확인할 수 없는 값은 생성하지 않고 미확인 상태로 반환한다.
- 모델의 제안과 외부 서비스에서 조회한 사실을 화면과 응답에서 구분한다.

### 5.5 신뢰성

- 비동기 작업의 대기·진행·성공·실패 상태를 확인할 수 있어야 한다.
- 중복 요청이 중복 데이터나 중복 비용을 만들지 않도록 한다.
- 일부 처리 실패 시 원본과 성공한 결과를 보존한다.
- 화면을 벗어나도 작업 상태를 다시 조회할 수 있어야 한다.

## 6. 공통 응답 상태 제안

AI API의 상세 스키마는 EODI-76에서 확정한다. 기능 간 상태 표현은 아래 기준을 공통으로 사용한다.

| 상태 | 의미 |
|---|---|
| `PENDING` | 처리를 기다리는 중 |
| `PROCESSING` | 처리 중 |
| `SUCCEEDED` | 정상 처리 완료 |
| `PARTIAL_SUCCESS` | 일부 항목만 처리 완료 |
| `INSUFFICIENT_DATA` | 처리에 필요한 자료가 부족함 |
| `NO_RESULT` | 정상 처리했지만 후보나 결과가 없음 |
| `NEEDS_CONFIRMATION` | 사용자 확인이나 선택이 필요함 |
| `FAILED` | 처리 오류가 발생함 |

각 응답은 최소한 다음 정보를 제공해야 한다.

- 요청과 결과를 추적할 수 있는 식별자
- 처리 상태
- 결과 데이터 또는 후보 목록
- 사용자에게 공개할 수 있는 근거
- 사용한 입력 범주의 요약
- 실패 코드와 재시도 가능 여부
- 결과 생성·갱신 시각

## 7. 구현 및 검증 순서

### 1단계: 입력과 데이터 경계 확정

- 지원할 링크·캡처 형식 정의
- 장소 동일성 및 그룹 겹침 기준 정의
- 취향의 직접 입력·추론·공유·철회 정책 정의
- 외부 모델 전송 데이터와 보존 범위 정의

### 2단계: 기술 검증

- 링크·캡처 장소 식별 정확도와 실패 유형 검증
- 후보 모델의 한국어·이미지 처리 품질, 응답 시간, 비용 검증
- 사진 주제 분류와 유사 사진 묶기 품질 검증
- 실제 날씨 데이터 기반 대안·준비물 생성의 사실성 검증

### 3단계: 추천 기준 검증

- 그룹 저장 겹침과 개인 취향 반영 여부 확인
- 겹침이 없는 그룹과 신규 사용자 처리 확인
- 비공개 데이터가 추천 결과와 이유에 노출되지 않는지 확인
- 좋아요·평점·실제 방문 신호가 구분되는지 확인

### 4단계: API·백엔드 연동

- 비동기 작업 생성·상태 조회·실패 재시도 설계
- 입력·출력 스키마와 오류 코드 확정
- 사용자 보정 결과 저장 및 재처리 연동
- 권한 변경과 삭제가 진행 중인 작업과 파생 결과에 미치는 영향 처리

## 8. 성공 조건

아래 조건을 만족하면 AI 기능의 기본 동작이 검증된 것으로 본다.

- 링크·캡처에서 식별한 장소를 사용자가 후보 중 선택하거나 직접 보정할 수 있다.
- 추천 결과가 그룹 저장과 허용된 취향을 어떻게 반영했는지 설명한다.
- 겹침 없음, 자료 부족, 결과 없음, 처리 실패를 구분한다.
- 날씨 대안과 준비물이 실제 조회 데이터에 근거하며 확인되지 않은 사실을 만들지 않는다.
- 사진 분류와 유사 묶음을 사용자가 수정할 수 있고 원본이 보존된다.
- 비공개 데이터가 다른 사용자의 추천 결과나 설명에 노출되지 않는다.
- 일부 처리 실패와 재시도 상황에서도 기존 확정 코스와 성공 결과가 보존된다.
- 기능별 처리 시간, 실패율, 호출 비용을 측정할 수 있다.

정확도·응답 시간·비용의 수치 목표는 실제 모델과 외부 서비스 검증 후 확정한다.

## 10. 현재 AI 범위에서 제외

- AI가 확인되지 않은 여행 사실·날씨·영업정보·좌표를 생성하는 기능
- 비공개 데이터와 채팅 내용을 동의 없이 추천에 활용하는 기능
- 추천 결과를 사용자 승인 없이 확정 일정에 반영하는 기능
- 유사 사진 원본 자동 삭제
- 베스트 컷 자동 선정
- 하이라이트 영상 생성
- 실제 송금·결제 처리
- 모델이 경로·이동 시간·경비를 임의 계산하는 기능
