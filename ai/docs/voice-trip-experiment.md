# 말로 새 여행 만들기 (실험, 앱 화면은 브랜치 `exp/voice-plan-chat`)

> 여행 탭 [+ 새 여행]을 누르면 **말로 만들기**와 **직접 입력하기**(지금 화면) 중 하나를 고른다.
> 말로 만들기는 어디로·언제·날마다 뭐 할지 쭉 말하면(최대 10분) 여행 정보와 코스 초안을 만든다.
> 잘 되는지 보고 DEV에 넣을지 정한다. AI·백엔드 API는 dev에 있고(앱 화면은 아직 실험 브랜치),
> 앱은 백엔드 `/api/v1/voice-trip`을 부르고 백엔드가 내부 AI 서버로 넘긴다.

## 1. 흐름

1. [+ 새 여행] → 고르기 창 → **말로 만들기**. (AI 서버 주소가 없는 빌드는 지금처럼 바로 입력 화면으로 간다)
2. 쭉 말하기: 들어가면 바로 듣는다. 최대 10분, [멈춤]/[이어서]로 쉬어도 된다. 전화 등으로 앱을 벗어나면 멈춘다(버리지 않음). ✓로 끝낸다.
   마이크를 못 쓰면 연필 버튼으로 글을 쓴다.
3. 정리 중: 받아쓰기 → 여행지·날짜·날마다 할 일 나누기 → 장소 찾기(N곳 중 M곳) → 초안. 다른 화면으로 가도 계속되고,
   다 되면 앱 안 안내(보기)와 여행 탭 위 띠로 알린다.
4. 초안: 위는 여행 정보(이름·어디로·언제), 아래는 날마다 코스. 항목마다 받아쓴 말을 붙인다.
   - 말한 것만 넣는다. 말하지 않은 여행지·날짜는 "말하지 않았어요 · 정하기", 말하지 않은 날은 빈 칸.
   - 이름은 말하지 않았으면 AI가 지어 "AI가 지었어요"로 표시한다.
   - 종류만 말한 곳("돼지국밥")은 AI가 한 곳을 골라 넣고 "AI가 고른 곳이에요 · 바꾸기". 바꾸기는 그날 앞 장소에서 가까운 후보 + 검색.
   - 시각은 말한 것만 적고, 끼니·때(점심·저녁)는 말한 대로 적는다.
5. 고치기: **말로 고치기**(1분 녹음 또는 글) → 바뀐 것 목록과 파란 표시, [되돌리기]/[좋아요]. **손으로 고치기**는 위/아래/빼기/장소 넣기.
   이름·여행지·날짜는 각 줄의 [고치기]로.
6. **여행 만들기**: 여행지 이름 → 지역 검색으로 맞춤 → 여행 만들기(멱등 키) → 장소를 우리 장소로(같은 이름·300m 안이면 그 장소, 없으면 위치로 새로) → 코스 저장 → 여행 상세.
   날짜 없이 코스가 있으면 "날짜 정하기 / 코스 없이 만들기"를 묻는다.

## 2. API

### 백엔드 (`EodiLog/.../voicetrip`, 로그인 필요)

AI 서버 API를 같은 모양으로 넘긴다(응답 본문 그대로). 저장하는 것은 없다.

| API | 하는 일 |
| --- | --- |
| `POST /api/v1/voice-trip/jobs` (multipart `audio` 또는 `text`) | AI 작업을 만들고 만든 사람을 40분 기억한다. 202 |
| `GET /api/v1/voice-trip/jobs/{jobId}` | 만든 사람만 본다(아니면 404) |
| `POST /api/v1/voice-trip/fixes` (multipart `draft` + `audio` 또는 `text`) | 그대로 넘긴다. 읽기 제한 90초 |
| `POST /api/v1/voice-trip/candidates` (JSON) | 그대로 넘긴다 |

- AI의 400·404·422(`INPUT_LIMIT_EXCEEDED`, `INSUFFICIENT_DATA`)는 문구째 넘기고, 401(내부 토큰)·5xx·연결 실패는 503 `AI_UNAVAILABLE`로 바꾼다(앱이 로그아웃으로 오해하지 않게).
- 만든 사람 기록은 백엔드 메모리에 있다. 백엔드를 다시 켜면 진행 중이던 작업은 다시 만들어야 한다.

### AI 서버 (`ai/app/features/voice_trip`, 내부 토큰)

| API | 하는 일 |
| --- | --- |
| `POST /ai/v1/voice-trip/jobs` (multipart `audio` M4A≤10분·12MiB, 웹은 webm / 또는 `text`) | 202 + 작업. 정리는 요청 밖에서 돈다(10분 녹음은 45초 요청 상한을 넘을 수 있다) |
| `GET /ai/v1/voice-trip/jobs/{jobId}` | `status` RUNNING/SUCCEEDED/FAILED, `step` TRANSCRIBING→UNDERSTANDING→SEARCHING→DONE, `searched/toSearch`, `draft` |
| `POST /ai/v1/voice-trip/fixes` (multipart `draft` JSON + `audio`≤60초 또는 `text`) | `{transcript, ops, changes}`. ops: setTitle·setDestinations·setDates·add·remove·move·setTime·replace |
| `POST /ai/v1/voice-trip/candidates` (JSON `{query, destination, near}`) | 네이버 검색 후보, near가 있으면 가까운 순 |

- 초안 `draft`: `title, titleByAi, destinations[{name,said}], startDate, endDate, datesSaid, dayCount, items[{key, day, said, label, startTime, query, place, aiPicked}], transcript`.
- LLM은 받아쓴 글에서 말한 것만 뽑고, 서버가 날짜(거꾸로·10일 넘음은 버림)·일차 범위·시각 형식·중복을 거른다. 연도 없는 날짜는 서울 오늘 기준 가장 가까운 날.
- 장소: 검색어에 여행지 이름이 없으면 "부산 + 검색어"로 먼저 찾는다. 이름을 말했는데 1등 결과와 많이 다르면(유사도 0.6 미만) 'AI가 고른 곳'으로 표시한다.
- 고치기의 변경 목록은 서버가 ops로 만든다(LLM 문장을 그대로 보이지 않는다). 못 찾은 곳은 "'…'은 지도에서 찾지 못했어요".
- 받아쓴 글·고칠 말은 자료로만 넘긴다(그 안의 지시를 따르지 않는다). 원음은 받아쓴 뒤 바로 놓는다. 작업은 서버 메모리에 30분만 두고 저장하지 않는다. 로그에는 개수·시간만 남긴다.

## 3. 실제로 돌려 본 것 (2026-11-16, GMS `whisper-1` + `gpt-5.6-luna`, 네이버 지역 검색)

| 항목 | 결과 |
| --- | --- |
| 글로 보낸 부산 2박 3일 계획 | 8.6~9.2초. 이름 "친구들과 부산 2박 3일", 부산, 11.20~11.22, 1일차 해운대 → 12:00 점심 돼지국밥(AI) → 오후 광안리 카페(AI) → 저녁 민락동 횟집(AI), 2일차 흰여울문화마을·감천문화마을·저녁 자갈치시장, 3일차 비움 |
| 녹음(Windows 한국어 음성으로 만든 27초 M4A) | 13초. 받아쓰기 "밀락동", "희녀울 마을"로 틀렸지만 검색으로 민락동 횟집·흰여울문화마을을 찾음(흰여울은 이름이 달라 'AI가 고른 곳'으로 표시) |
| 말로 고치기 "날짜 하루 미뤄서 21일부터, 둘째 날 점심은 남포동 밀면" | 2.4~3.1초. 날짜 11.21~11.23, 2일차 점심에 남포동 밀면집(저녁 앞 자리) |
| 후보(해운대 돼지국밥, 앞 장소 기준) | 450m~760m 5곳 |
| 웹 미리보기(테스트 모드), 폰 크기 | 고르기 창 → 쭉 말하기 → 글로 쓰기 → 정리 중 → 초안 → 말로 고치기 → 후보 → 여행 만들기 → 여행 상세(코스 짜기 ✓) |

아직 안 본 것: 실제 폰 마이크로 5~10분 말하기, 시끄러운 곳, 여행지가 여러 곳일 때의 지역 맞추기.
웹 미리보기만의 문제: 시트 안 입력칸이 닫힐 때 react-native-web 오류(`currentlyFocusedInput`)가 뜬다(gorhom 시트, 폰은 해당 없음).

## 4. 폰에서 시험하기

보통은 백엔드를 거치므로 따로 할 것이 없다. 노트북 AI 서버로 바로 시험할 때만:

```
# 노트북: AI 서버 (ai/.env의 GMS·네이버 키를 쓴다)
cd ai
ALLOW_NO_INTERNAL_TOKEN=true uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
# 폰: USB 연결 뒤
adb reverse tcp:8000 tcp:8000
```

앱을 `EXPO_PUBLIC_VOICE_PLAN_URL=http://localhost:8000`으로 빌드하면 백엔드 대신 그 AI 서버를 바로 부른다.

## 5. DEV에 넣는다면

- **백엔드**: 지금은 얇게 넘기기만 한다. 정식으로는 작업(Job)으로 상태를 DB에 들고, 다 되면 **푸시 알림**을 보낸다.
  초안은 여행이 생기기 전이라 사용자 단위로 잠시 둔다.
- **여행 만들기**: 지금은 앱이 지역 맞추기·여행 만들기·장소 만들기·코스 저장을 차례로 부른다. 백엔드 API 하나(초안 → 여행+코스)로 묶는 편이 안전하다(중간 실패 시 반쯤 만든 여행이 남지 않게).
- **장소**: AI가 찾은 네이버 장소를 앱이 우리 장소 검색으로 맞추고 없으면 수동 장소로 만든다. 백엔드 장소 resolver로 맞추는 편이 낫다.
- **프론트**: `frontend/src/features/voice-trip`, 여행 탭 [+ 새 여행] 고르기 창과 띠, 라우트 `trips/new-voice`·`trips/voice-draft`. 프론트 담당과 디자인을 맞춘다.
- **비용**: 초안 1번에 받아쓰기 1번(최대 10분) + LLM 1번 + 장소 검색 항목 수만큼. 고치기 1번에 받아쓰기·LLM 1번씩.
