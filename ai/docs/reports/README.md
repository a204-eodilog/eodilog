# AI 기능 PoC 평가 종합

dev의 AI 기능을 실제 모델로 호출해, 명세대로 동작하는지와 결과가 쓸 만한지 확인했다. 기능마다 입력 세트를 먼저 정하고 실행했으며, 아래 수치는 모두 결과 파일에서 계산했다. 라벨과 "Claude 판정"은 Claude가 매긴 것이고 사람 검토가 아니다.

| ID | 기능 | 내용 | 상태 |

| B1 | 취향 추정 | 네이버 분류(`한식>국밥`)의 음식점이 규칙에서 빠져, LLM 장애 때 `맛집`이 사라짐 | 수정(!142) |

| B3 | 준비물 제안 | 지운 `선크림`이 `자외선 차단제`로 다시 제안됨(2/2회) | 수정 중 |

| R3 | 사진 분류 | 고해상도 JPEG 한 장이 15MB 제한을 넘음. 50장 요청은 약 118MB | 백엔드와 본문 크기 확인 필요 |

## 한계

- 평가 세트가 작다(기능당 17~92건). 몇 건 차이는 우열의 근거로 삼지 않는다.
- 사진과 캡처는 Wikimedia Commons 사진이고 사용자 사진이 아니다. HEIC는 없다.
- 지연 시간은 개발 PC(Intel Core Ultra 9 185H)와 H200 기준이다. EC2 c6g는 측정하지 않았다.
- LLM 결과는 실행마다 달라진다. 준비물 제안은 두 회차 출력이 7/18만 같았다.

## 다음 단계

1. 네이버 키를 넣고 장소 추출을 장소 검색까지 다시 평가한다.
2. B2, B3, R2 수정을 병합한 뒤 같은 세트로 다시 잰다.
3. 팀원 휴대폰 사진 100장 이상을 사람이 라벨링해 사진 분류를 다시 잰다.
4. EC2 c6g에서 `scripts/eval_photos.py --latency-only`로 지연을 잰다.
