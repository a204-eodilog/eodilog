## 남은 확인

- CLIP 분류 정확도는 **실제 여행 사진**으로 다시 재야 한다. 그린 그림이라 동작 확인일 뿐이다. 하늘 그림의 PEOPLE 점수가 0.32로 높게 나와 임계값(0.4) 조정이 필요할 수 있다.
- Windows에서 PyPI torch는 CPU 빌드다. GPU 서버(Linux)에서 속도를 다시 잰다.
- 링크 추출은 실제 SNS 링크로 확인하지 않았다. 인스타그램 등은 봇 요청을 막아 메타데이터가 비어 있을 가능성이 크다(plan §6).
- 카카오 키워드 검색이 이름이 비슷한 다른 곳을 줄 수 있다(예: '청사포 카페' → '청사포역'이라는 카페). 후보는 항상 사용자가 확인한다.

## 모델 비교: CLIP vs SigLIP2 (2026-10-27, 로컬 CPU)

`scripts/compare_models.py`, 같은 평가 사진 60장·같은 주제 문장. top-1 = 가장 높은 주제를 골랐을 때 정확도.

| 모델 | top-1 (영어 문장) | top-1 (한국어 문장) | 장당 (CPU) | 로딩 | 유사 쌍 최소 | 비유사 쌍 최대 |
| --- | --- | --- | --- | --- | --- | --- |
| CLIP ViT-B-32 (현재) | 96.7% | 41.7% | 23ms | 1s | 0.979 | 0.888 |
| SigLIP2 ViT-B-32-256 | 98.3% | 93.3% | 32ms | 12s | 0.966 | 0.915 |
| SigLIP2 ViT-B-16 | 98.3% | 95.0% | 77ms | 76s | 0.967 | 0.936 |

- 정확도 차이는 1~2장 차이라 60장으로는 의미 있는 차이가 아니다. 영어 문장은 CLIP 기준으로 조정한 것이라 CLIP에 유리한 비교다.
- CLIP은 사진 축소 방식에 따라 경계 사례(등산객 사진)가 흔들려 96.7~98.3%를 오간다.
- SigLIP2는 한국어 문장으로도 93~95%. CLIP은 한국어 문장을 거의 못 쓴다(41.7%).
- 유사 묶음은 CLIP이 가장 잘 나뉜다(간격 0.091). SigLIP2-B16은 비유사 쌍이 0.936까지 올라가 지금 기준 0.92를 쓰면 잘못 묶인다. SigLIP2로 바꾸면 기준을 0.95 안팎으로 다시 잡아야 한다.
- 임계값('최고 점수가 낮으면 기타') 규칙은 세 모델 모두 이득이 없었다(최적 0.00).

## 사진 모델을 SigLIP2로 전환 (2026-10-27)

- 운영 모델: `ViT-B-32-SigLIP2-256` (webli). 점수는 sigmoid(scale·유사도 + bias), 주제는 가장 높은 점수.
- 유사 묶음 기준 0.92 → **0.94** (유사 쌍 최소 0.966, 비유사 쌍 최대 0.915의 중간).
- 서비스 경로(`eval_photos.py`) 결과: 정확도 **98.3%** (틀림: 수산시장 게 사진 → 사람), 유사 쌍 8/8, 잘못 묶임 0.
- 로컬 CPU 장당: 디코딩 24ms + 모델 85ms. 같은 경로의 CLIP(38ms)보다 약 2.2배 느리다(비교 스크립트의 1.4배보다 큼). c6g에서 다시 잰다.
- GPU 서버·로컬 `.env`의 `CLIP_MODEL`, `CLIP_PRETRAINED`도 바꿔야 한다(예전 값이 남아 있으면 CLIP으로 돈다).

## 취향 추론 동작 확인 (2026-11-03, `gpt-5.6-luna`)

분류 없이 이름만 보낸 부산 장소 13곳과 지시문이 든 이름 1개를 한 번에 분류했다. 8.1초.

- 대체로 그럴듯했다: 감천문화마을 → 골목·사진, 광안대교 → 야경, 스파랜드 → 휴식. 지시문 이름은 태그 없음.
- 사람이 보기에 어긋난 것: 금련산 청소년수련원 → 산, 국제시장·깡통시장 → 맛집. 정답표로 잰 정확도가 아니라 동작 확인이다.
- 응답 시간: 100곳 14.0초, 50곳 8.4초(1회씩). 요청당 100곳 제한이 LLM 제한 시간 30초 안에 든다.
- `category` 규칙은 카카오 형식 기준이다. 장소 검색이 네이버로 바뀌었으므로 실제 네이버 응답을 본 뒤 고쳐야 한다.

## 준비물 제안 동작 확인 (2026-11-03, `gpt-5.6-luna`)

부산 1박 2일 일정(비 70%, 최저 4°, 해수욕장, 지시문이 든 장소 이름 1개)으로 실제 GMS를 1회 호출했다. 5.8초.

- 규칙 제안 11개와 LLM 추가 `방수팩` 1개가 나왔다. 지시문의 `가짜물건`은 나오지 않았다.
- 동작 확인이며 제안 품질을 잰 값은 아니다. 백엔드 호출은 아직 없다.
- 걷는 장소·바다 판단은 장소 분류와 이름 낱말에 의존한다. 네이버 `category` 형식과 백엔드 `places.category` 제공 여부가 정해지면 다시 확인한다.

## 사진 분류 API 구현 (2026-11-06 기준, 작업 12, !128)

코드: `ai/app/features/photo_classification`. 설정 기본값은 `ai/app/core/config.py`.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 모델 | `ViT-B-32-SigLIP2-256`, `webli` 가중치 | `clip_model`·`clip_pretrained` 기본값 |
| 유사 묶음 기준 | 코사인 0.94 이상, 연결된 사진은 한 묶음 | `photo_similarity_threshold`, `group_similar` |

| 자동 테스트 | `tests/test_photo_classification.py` 48개 통과(가짜 임베딩, T-08-1 ~ T-08-6 포함) | 2026-11-06 실행 |

- 테스트는 실제 모델을 쓰지 않는다. 아래는 이 구현으로 잰 적이 없다.

- 448px 축소가 정확도·유사도에 주는 영향: **미측정**. 0.94 기준은 연습 구현 측정값에서 정했다.
- 장당 처리 시간, 사진 50장 처리 시간, 모델 로딩 시간(로컬·EC2 c6g): **미측정**.

## 사진 주제: 실내는 기타 (2026-11-06)

PoC 평가(77장, 94.8%)에서 호텔 객실과 박물관 중앙홀이 `LANDSCAPE`로 나왔다. 풍경 문장 "a photo of a city street and buildings"에 끌린 것으로 보았다. 음식·사람이 주인공이 아닌 실내를 `OTHER`로 정하고(spec §8.1) 주제 문장만 바꿨다.

- 풍경 문장 3개에 "outdoor"를 넣었다.
- 기타에 실내 문장 4개를 더했다: 실내 방, 호텔 객실, 박물관·미술관 내부, 가게·카페·기차 내부.

평가 세트 두 개, 서비스 경로(`POST /ai/v1/photo-classifications`, 사진마다 1장짜리 요청), `ViT-B-32-SigLIP2-256`, 로컬 CPU.

- 원본 77장: PoC 평가와 같은 세트(파생본 15장 제외).
- 새 세트 30장 `ai/eval_data/photos_holdout`: 문장을 고르기 전에 Commons에서 받아 정답을 먼저 붙였다(Claude가 접촉 시트를 보고 붙임, 사람 검수 전). 실내 `OTHER` 18장(호텔 객실 5, 박물관·미술관 5, 카페 3, 기차·지하철 3, 가게 2)과 바깥 `LANDSCAPE` 12장(거리 5, 건물·도시 전경 7)이다. 라이선스는 CC0, CC BY, CC BY-SA만 받았고 `sources.csv`에 적었다. 커밋하지 않는다.
