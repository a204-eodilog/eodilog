# 자체 비전 LLM과 GMS 비교 실험 (EODI-209)

캡처 장소 추출에서 H200 자체 서빙 모델과 GMS를 같은 조건으로 비교한다. 결론은 "현재 구성 유지" 또는 "자체 모델 추가 검토"다. 서비스 경로와 운영 배포는 바꾸지 않는다.

상태: 후보 1 평가 완료, 후보 2 미실행. 3번 장치는 여러 팀이 함께 쓰므로 메모리를 전체의 3분의 1 아래로 제한해 실행한다.

## 비교 대상

| 구분 | 모델 | 선택 이유 |
| --- | --- | --- |
| 기준선 | GMS `gpt-5.6-luna`, `gpt-5.5`, `gpt-4.1` | 2026-11-03 저장 결과 |
| 후보 1 | `Qwen3-VL-4B-Instruct` | vLLM 공식 지원 |
| 후보 2 (조건부) | EXAONE 4.5 | 한국어 OCR 데이터를 학습에 사용. vLLM 지원과 라이선스 확인 후 진행 |

## 평가 세트

- `ai/eval_data/places` 50장: 양성 38장, 음성 12장.
- 사진은 Wikimedia Commons 출처이고 사용자 사진이 아니다. 출처와 라이선스는 `sources.csv`에 있다.
- `labels.json`은 실행 전에 고정한다. 결과를 본 뒤 고치면 사유를 기록하고 모든 모델을 다시 채점한다.

## 고정 조건

- 프롬프트는 서비스의 `SYSTEM_PROMPT`를 그대로 쓴다.
- 이미지는 서비스와 같은 1600px JPEG로 변환하고, 요청당 1장을 보낸다.
- 네이버 장소 검색은 빼고 LLM이 찾은 이름만 비교한다.
- 채점은 `scripts/eval_places.py`의 `score_image`를 쓴다.
- 자체 모델은 GPU 서버 안에서 `CUDA_VISIBLE_DEVICES=3`, vLLM OpenAI 호환 API(`127.0.0.1`)로 호출한다.

## 측정 항목

| 항목 | 정의 |
| --- | --- |
| 양성 정답 | 양성 38장 중 대표 장소 이름을 맞힌 수 |
| 음성 통과 | 음성 12장 중 장소를 내지 않은 수 |
| 지어낸 이름 | `unexpected`를 사람이 사진과 대조해 실제로 없는 이름만 센다 |
| 지연 | 중앙값, 최댓값. 모델 로딩 시간은 따로 기록 |
| 안정성 | 오류와 JSON 파싱 실패 수 |
| 자원 | GPU 메모리 최고치, 모델 디스크 용량 |
| 비용 | GMS는 호출 수와 토큰. 자체 모델은 자원 사용량으로 기록 |

## 현재 기준선

저장된 응답을 API 호출 없이 다시 채점했다.

| 모델 | 양성 정답 | 음성 통과 | `unexpected` 사진 | 지연 중앙값 | 지연 최댓값 |
| --- | --- | --- | --- | --- | --- |
| `gpt-4.1` | 35/38 (92.1%) | 11/12 | 10장 | 1.54초 | 4.16초 |
| `gpt-5.5` | 33/38 (86.8%) | 12/12 | 13장 | 4.93초 | 15.12초 |
| `gpt-5.6-luna` | 32/38 (84.2%) | 12/12 | 10장 | 3.32초 | 7.20초 |

- `unexpected`는 사람이 아직 판독하지 않았다. 사진에 실제로 있는 글자일 수 있어 지어낸 이름 수로 쓰지 않는다.
- 저장 결과에 장소 검색이 연결된 항목은 0건이다.
- `gpt-5.6-luna`를 2026-11-05에 `--no-places`로 다시 쟀다. 양성 33/38, 음성 12/12, `unexpected` 8장, 오류 0건, 지연 중앙값 3.34초, 최댓값 7.41초. 저장 결과와 지연이 거의 같고, 같은 사진에서도 답이 달라질 수 있다. 자체 모델도 여러 번 돌려 비교한다.

## 후보 1 결과: `Qwen3-VL-4B-Instruct` (2026-11-05)

환경: GPU 3번, vLLM 0.19.0, torch 2.10.0+cu128, `--gpu-memory-utilization 0.25`. 서버 드라이버가 CUDA 12.8이라 CUDA 13용 vLLM 0.20 이상은 실행되지 않았다. 측정 중 `j-k15a203` 프로세스 8개가 3번 장치에서 함께 떠 있어, 지연은 참고값이다.

| 회차 | 양성 정답 | 음성 통과 | `unexpected` 사진 | 오류 | 지연 중앙값 | 지연 최댓값 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 18/38 (47.4%) | 11/12 | 18장 | 0 | 0.70초 | 4.32초 |
| 2 | 21/38 (55.3%) | 11/12 | 19장 | 0 | 0.43초 | 0.82초 |
| 3 | 20/38 (52.6%) | 11/12 | 16장 | 0 | 0.47초 | 0.80초 |

- GPU 메모리 25.0GB 사용. 1회차 앞 5장은 시험 실행 결과를 이어서 썼다.
- 양성 38장 중 16장은 3회 모두 틀렸다.
- 실패 유형: 아무 이름도 내지 않음(`008`, `023`, `052`), 글자를 잘못 읽음(`010` 풍림 → 동림, `028` 깨진 문자열), 이름 일부만 읽음(`030` 가마치통닭 → 가마치, `048` 황금무지개송어회 → 송어회).
- 음성 `069.jpg`는 3회 모두 장소를 냈다.
- 판단 기준의 양성 정답 33/38과 음성 12/12를 넘지 못해 이 모델은 "현재 구성 유지"다. 프롬프트는 서비스용 그대로 두었고 이 모델에 맞추지 않았다.
- 지어낸 이름 수는 `unexpected`를 사람이 판독한 뒤 확정한다.

## 판단 기준 (제안)

아래를 모두 만족하면 "자체 모델 추가 검토", 아니면 "현재 구성 유지"로 결론 낸다.

- 양성 정답 33/38 이상 (85% 이상)
- 지어낸 이름 0건
- 음성 통과 12/12
- 오류와 JSON 파싱 실패 0건
- 지연 중앙값 5초 이하

평가 세트가 작아 양성 1장이 2.6%p다. 몇 장 차이는 우열의 근거로 삼지 않고, 차이가 난 사진을 함께 기록한다.

통과해도 바로 서비스에 쓰지 않는다. GPU 서버 8000번은 외부에서 막혀 있어, 사용하려면 운영 측이 허용한 경로가 먼저 필요하다.

## 실행 순서

사용자 확인 후에만 진행한다.

1. 주피터 서버를 켜고 디스크와 3번 장치의 사용 상태를 확인한다.
2. 프로젝트와 분리한 가상환경에 vLLM을 설치하고 모델을 내려받는다.
3. 평가 사진을 서버로 옮기고 3번 장치에서 vLLM을 실행한다.
4. 5장으로 시험한 뒤 50장을 평가한다.
5. vLLM을 종료하고, 결과를 내려받아 `unexpected`를 사람이 판독한다.
6. 비교표와 실패 사례를 `verification.md`에 기록한다.

평가 스크립트는 고치지 않는다. `GMS_BASE_URL`, `GMS_API_KEY`, `--no-places`로 실행한다. vLLM은 `--served-model-name`으로 `/` 없는 모델 이름을 지정한다. 3번 장치를 다른 프로세스가 쓰고 있으면 그 프로세스를 건드리지 않고 멈춘 뒤 확인을 요청한다.
