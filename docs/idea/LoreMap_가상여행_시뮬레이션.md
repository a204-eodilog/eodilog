# LoreMap — AI 가상 여행 시뮬레이터

> **한 줄 소개**  
> **실제 여행을 떠나기 전에 하루 여행 코스를 가상으로 따라가 보고, 마음에 드는 장소를 직접 고르면서 일정을 완성하는 서비스**

- 문서 유형: 팀 아이디어 공유 및 6주 MVP 논의용 기획서
- 기획 기준일: 2026-10-14
- 서비스명: **LoreMap (가칭)**
- 기획 단계: **제안안**. 제품의 차별성과 기술 구현 가능성은 검증 전입니다.
- 참고: 기존 `LoreMap 컨설팅.html`의 아이디어를 바탕으로 방향을 변경했습니다.

---

## 0. 30초 요약

여행을 준비할 때 사진과 후기만으로는 **그 장소가 실제로 어떤 분위기인지, 다른 장소와 이어서 방문하기 좋은지** 판단하기 어렵습니다.

LoreMap은 추천 장소를 지도 위 목록으로 보여주는 데 그치지 않습니다. 사용자는 하루 일정의 첫 장소부터 마지막 장소까지 **가상으로 하나씩 방문**합니다. 현장 사진이나 360도 화면으로 장소를 둘러보고, 여행할 시기에 대한 **AI 참고 이미지**도 비교합니다. 마음에 들면 일정에 남기고, 기대와 다르면 제외합니다. 이때 AI는 제외한 이유를 반영하고, 실제 이동 시간과 운영 정보 등을 검토해 **다음 코스를 다시 제안**합니다.

**핵심 MVP는 딱 하나입니다.**

> **「가상 방문 → 방문 여부 결정 → 여행 코스 변경」의 흐름을 한 번에 경험하게 만들기**

여행 일기, 공동 앨범, 판타지 스토리, 영상 생성 등은 이번 MVP에서 제외합니다.

## 1. 왜 필요한 서비스인가?

### 사용자가 겪는 문제

- 검색 결과의 대표 사진은 멋있지만, 내가 방문할 시간대나 계절의 분위기와 다를 수 있습니다.
- 사진 여러 장을 보더라도 **장소 사이의 이동 부담**과 하루 전체의 흐름을 체감하기 어렵습니다.
- 기존 여행 계획 도구에서 추천 코스를 받아도, **어느 장소가 나에게 맞는지 판단하는 과정**은 여전히 사용자 몫입니다.
- '전망은 좋지만 사람이 많아 보인다', '풍경은 좋은데 너무 오래 걸어야 한다' 같은 **결정 이유가 일정 수정에 반영되지 않으면** 검색을 다시 해야 합니다.

### 해결하고 싶은 문제

> **여행지가 마음에 드는지 가기 전에 판단하기 어려운 문제**를, 실제 장소 자료를 활용한 단계별 가상 관광과 선택형 일정 수정으로 줄입니다.

### 대상 사용자

**우선 대상:** 낯선 도시에서 1일 관광 일정을 짜려는 20~30대 자유여행객. 사진과 리뷰를 여러 번 찾아보며 방문 장소를 비교하는 사람을 상정합니다. 이는 초기 사용자 가설이며 실제 인터뷰가 필요합니다.

**대표 사용 상황:** '교토에서 하루를 보낼 예정인데 관광지를 3~4개 방문하려고 합니다. 사진만 보고 결정하기 어려워서 미리 둘러보고 싶어요.'

## 2. 서비스의 핵심 콘셉트

### 기존 방식과 LoreMap의 차이

| 단계 | 일반적인 여행 계획 방식 | LoreMap이 제공하려는 경험 |
|---|---|---|
| 후보 발견 | 검색, 리뷰, 추천 목록 확인 | 여행 조건에 맞춘 장소 후보 제안 |
| 장소 비교 | 사진·후기·지도에서 각자 확인 | 장소별 실제 화면을 이어서 가상 방문 |
| 방문 여부 결정 | 즐겨찾기 또는 수동으로 목록 편집 | 가상 방문 직후 **유지/제외 + 이유** 입력 |
| 일정 수정 | 조건을 다시 설명하거나 직접 재배열 | 선택 이유를 반영해 다음 장소와 경로 재구성 |
| 결과 | 관광지 목록·지도상의 동선 | **직접 미리 체험해 선택한** 하루 일정 |

여기서의 차별성은 '관광지를 3D로 보여준다'가 아닙니다. **시각적 체험이 실제 여행 의사결정과 연결된다는 점**입니다. 다만 이 조합이 시장에 전혀 없다는 주장은 하지 않습니다.

### 제품 원칙 세 가지

1. **실제와 상상을 구분합니다.** 실제 현장 사진·360도 뷰와 AI가 추정해 생성한 장면을 명확히 나눠 표시합니다.
2. **AI가 일정을 임의로 확정하지 않습니다.** 사용자의 방문 여부 결정이 우선이고, AI는 대안을 제안합니다.
3. **보는 데서 끝내지 않습니다.** 모든 체험 화면에 '일정에 유지', '제외', '다른 장소 보기'와 같은 다음 행동을 제공합니다.

## 3. 사용자는 어떻게 이용하나요? — 하루 여행 예시

> 아래는 서비스 동작을 설명하기 위한 **가상 시나리오**입니다. 실제 장소의 영업시간·이동 시간이나 관광 추천 결과가 아닙니다.

**상황:** 친구와 함께 교토 자유여행을 준비하는 사용자. 하루 중 주요 관광지 3곳을 둘러보려고 합니다.

**① 여행 조건 입력**  
'교토 / 하루 / 걷는 양은 적게 / 전통 거리와 풍경을 좋아함'을 선택합니다.

**② 첫 일정 제안**  
AI가 관광지 후보와 방문 순서를 지도에 보여줍니다. 사용자는 '가상으로 먼저 둘러보기'를 누릅니다.

**③ 하루 여행 시뮬레이션 시작**  
오전 첫 관광지의 실제 사진이나 360도 장면을 봅니다. 화면에는 현재 코스의 순서와 다음 이동 구간이 표시됩니다. 이용 가능한 경우 시간대·계절별 참고 이미지도 볼 수 있습니다.

**④ 방문 여부 결정**  
첫 장소는 '유지'합니다. 두 번째 장소는 풍경은 마음에 들지만 도보 이동이 부담스러워 '제외'합니다. 제외 이유로 **'너무 많이 걸어야 해요'**를 고릅니다.

**⑤ 코스 즉시 수정**  
시스템이 '도보 이동 최소화' 선호를 반영해 대체 후보를 제안하고, 지도 및 예상 이동 시간을 갱신합니다. 사용자는 대체 장소도 가상 방문한 다음 선택합니다.

**⑥ 여행 계획 완성**  
선택한 관광지와 방문 순서, 예상 이동 구간, 참고할 실제 장소 정보가 담긴 하루 코스를 저장합니다.

### 사용 흐름 한눈에 보기

```text
여행 조건 입력
      ↓
하루 코스 초안 생성
      ↓
[장소 1 가상 방문] ──→ 유지 / 제외 / 다른 장소 보기
      ↓                      ↓
[장소 2 가상 방문]      이유 기록 및 선호 반영
      ↓                      ↓
[장소 3 가상 방문] ←── 대체 장소 + 이동 경로 재계산
      ↓
최종 코스 검토 · 저장
```

## 4. 실제 화면에서 보여줄 것

| 화면 | 사용자에게 보이는 정보 | 핵심 동작 |
|---|---|---|
| **A. 여행 조건** | 지역, 날짜, 하루 여행 시간, 이동 수단, 선호 분위기 | 조건 입력 후 시뮬레이션 시작 |
| **B. 코스 미리보기** | 후보 장소 5~8곳, 방문 순서, 지도, 예상 이동 부담 | '이 코스로 체험하기' |
| **C. 가상 관광** | 실제 사진 또는 360도 장면, 장소 설명, 다음 장소, 일정상 위치 | 화면 둘러보기, 유지/제외 |
| **D. 선택 이유** | '많이 걸음', '분위기가 취향과 다름', '너무 붐빌 것 같음', 직접 입력 | 제외 이유 제출 |
| **E. 대체 코스** | 바뀐 장소, 바뀐 순서, 이동 시간 차이, 선택을 반영한 이유 | 대체안 수락/거절 |
| **F. 최종 일정** | 장소 목록, 시간표, 지도, 실제 정보 출처 | 코스 저장 및 공유 |

### 핵심 화면 C의 구성 예시

```text
┌───────────────────────────────────────────────────────┐
│ LoreMap · 교토 하루 여행                      2 / 4  │
├──────────────────────────────────┬────────────────────┤
│                                  │ 현재 관광지        │
│ [실제 사진 / 360° 현장 화면]     │ 이름 · 소개        │
│                                  │ 예상 체류시간      │
│ ※ 실제 촬영 자료 / 촬영 시점     │ 다음 장소까지 이동 │
│                                  │                    │
│ [조건별 AI 참고 이미지 보기]      │ [일정에 유지]      │
│                                  │ [제외하고 대체]    │
├──────────────────────────────────┴────────────────────┤
│ 오전 10:00 장소 A ─ 11:20 장소 B ─ 13:00 장소 C      │
└───────────────────────────────────────────────────────┘
```

*화면 구조는 와이어프레임 수준의 제안입니다. 실제 관광지·경로 데이터가 표시된 목업은 아닙니다.*

## 5. AI가 관광지 이미지를 어떻게 제공하나요?

관광지 이미지를 **AI가 전부 만들어 '실제 풍경'처럼 제공하는 방식은 피합니다.** 잘못된 건물 구조나 계절감을 만들어 사용자의 방문 결정을 오도할 위험이 있기 때문입니다.

| 이미지 유형 | 어떤 이미지인가? | 화면 표시 | MVP 처리 |
|---|---|---|---|
| **현장 사진** | 사용 권한이 확인된 실제 사진 | `실제 사진` + 출처·촬영 시점(알려진 경우) | **필수** |
| **360도 현장 화면** | 지원되는 지역의 Street View 또는 이용 권한이 있는 파노라마 | `현장 360°` + 제공자 표시 | **지원 장소에서 필수** |
| **AI 예상 장면** | 합법적으로 사용할 수 있는 참조 자료 또는 텍스트 설명으로 제작한 분위기 예시 | **`AI 생성 참고 이미지 · 실제와 다를 수 있음`** | **시범 1~2곳** |

**AI 이미지 예시:** '늦은 오후의 따뜻한 분위기라면 어떨까?' 같은 시각적 참고 장면. **특정 날짜의 실제 날씨, 단풍·벚꽃 절정, 혼잡도, 건물 구조를 정확히 재현한다고 주장하지 않습니다.**

**중요한 구현 제약:** Google 지도·Street View 자료를 임의로 내려받아 저장하거나 이미지 생성 AI에 입력하여 가공하는 것은 계약 및 사용 정책 검토가 필요합니다. 따라서 Google 제공 이미지는 **공식 뷰어로 직접 표시**하고, AI 참고 이미지 제작에는 별도로 사용·가공 권한을 확보한 자료를 사용하도록 설계합니다. [출처 S4, S5]

> **1주차 기술 검증 목표:** 현장 뷰어 연결이 가능한 관광지를 찾고, AI 이미지 생성에 사용할 적법한 참조 자료를 확보할 수 있는지 검사합니다. 충족하지 못하면 AI 이미지 생성은 제거하고, 실제 뷰 중심의 시뮬레이션을 먼저 완성합니다.

## 6. 핵심 MVP 범위 — 6주

### 반드시 만들 기능 (P0)

1. **하나의 여행 지역**에 대해 미리 검증한 관광지 **5~8곳** 제공
2. 사용자 조건(방문 가능 시간, 이동 수단, 선호 분위기) 입력
3. 후보 관광지를 이용한 **하루 일정 초안** 표시
4. 실제 사진과 지원되는 360도 화면을 이용한 **장소별 가상 방문**
5. **'유지 / 제외 / 대체'** 선택 및 제외 이유 저장
6. 변경된 선호와 이동 제약을 반영한 **코스 재구성**
7. 관광지별 실제 장소 정보와 **최종 여행 일정 저장·공유**

### 조건부 시범 기능 (P1)

- 적법한 자료를 확보한 **1~2개 관광지에 한정**해 시간대·분위기별 AI 참고 이미지 생성
- 실제 사진과 AI 참고 이미지를 나란히 비교하는 화면

### 이번에 만들지 않을 기능

- 거리를 자유롭게 걸어 다니는 **완전한 실시간 3D 월드**
- 도시 전체의 사진을 AI로 자동 재구성하는 디지털 트윈
- 실시간 인파·날씨의 시각적 정확도를 보장하는 예측
- 항공권·숙소 결제, 예약 대행
- 공동 여행 추억, AI 여행기, 판타지 스토리, 추억 영상 생성
- 전 세계 도시 지원

**범위를 이렇게 제한하는 이유:** 사용자에게 필요한 것은 '게임 수준의 3D 구현'이 아니라 **가상 관광을 하고 선택한 결과가 여행 계획에 반영되는지**이기 때문입니다.

### MVP 완료 기준 (데모 기준)

- 실제 자료가 있는 한 지역의 관광지 5곳 이상이 가상 체험에 표시됩니다.
- 사용자가 관광지 하나를 제외하고 이유를 선택할 수 있습니다.
- 그 이유에 따라 대체 관광지를 제안하고 일정의 방문 순서·이동 구간이 갱신됩니다.
- 실제 자료와 AI 생성 참고 이미지가 구분됩니다.
- 변경된 여행 코스를 저장하고 다시 열 수 있습니다.

## 7. AI는 정확히 어떤 일을 하나요?

AI 모델 한 번 호출로 모든 기능을 처리하는 대신 역할을 나눕니다.

| 역할 | 입력 | 출력 | 주의점 |
|---|---|---|---|
| **일정 후보 제안** | 여행 조건 + 검증된 장소 데이터 | 방문 장소·순서의 초안 | 존재하지 않는 장소를 만들어 내지 않도록 장소 ID 기반으로 처리 |
| **사용자 의도 해석** | '많이 걷기 싫어요' 같은 문장 | `도보 이동 최소화` 선호 조건 | 사용자의 말을 확인·수정 가능하게 표시 |
| **대체안 설명** | 후보별 특징, 이동 시간, 제외 이유 | 왜 이 장소를 제안했는지 설명 | 확인 가능한 자료와 추정을 구분 |
| **참고 이미지 생성** | 허용된 자료, 분위기 조건 | AI 생성 참고 장면 | 실제 사진과 동일한 사실 정보로 취급하지 않음 |

**AI에 맡기지 않을 것:** 정확한 좌표, 영업 상태, 경로 거리·시간 계산은 지도·장소 데이터와 규칙 기반 검증으로 처리합니다. 방문 가능 여부가 확인되지 않으면 '정보 확인 필요'로 표시합니다.

### 코스 변경 규칙의 간단한 예

```text
입력: 장소 B 제외 / 이유 = "걷는 시간이 너무 길어요"

1) 기존 일정에서 장소 B를 임시 제거
2) 방문 가능 후보 중 비슷한 성격의 장소 검색
3) 후보별 실제 이동 시간 및 운영 여부 확인
4) 이동 부담이 적은 후보부터 제안
5) 사용자가 대체안을 수락한 뒤 일정 확정
```

**가정:** 지도 API가 모든 구간의 정확한 이동 정보를 제공하지 않을 수 있습니다. 데이터가 없는 구간은 임의 숫자를 채우지 않고 사용자에게 안내합니다.

## 8. 기술 구현 구조(제안)

```text
웹 화면 (Next.js / React)
  ├─ 여행 조건·일정 편집
  ├─ 지도와 장소 카드
  └─ 실제 360도 뷰 / AI 참고 이미지
                │
                ▼
백엔드 API (Spring Boot 또는 FastAPI 등 팀 역량에 맞춰 선택)
  ├─ 사용자 선택 및 여행 일정 저장
  ├─ 장소/경로 API 호출 및 결과 검증
  ├─ AI 의도 분석·설명 요청
  └─ AI 참고 이미지 생성 요청 (조건부)
                │
       ┌────────┴────────┐
       ▼                 ▼
  PostgreSQL       외부 제공 서비스
  ├─ 여행 조건       ├─ 지도·장소·경로
  ├─ 선택 이력       ├─ 360도 현장 뷰어
  └─ 일정 상태       └─ LLM / 이미지 생성
```

### 검토할 API·자료

- **Google Maps JavaScript API / Street View Service:** 지원 구간의 상호작용형 파노라마 표시 [S3]
- **Places API:** 장소 ID, 위치, 운영 상태 및 영업시간 등 조회 [S6]
- **Routes API:** 장소 간 경로·거리·이동 시간 계산 [S7]
- **AI 모델 API:** 사용자의 제외 이유를 구조화하고 대체 이유 설명, 참고 이미지 생성(모델 선택 및 비용 검증 필요)

이 목록은 **후보 기술**이지, 제공 범위·요금·국가별 지원 여부를 검증했다는 뜻은 아닙니다. 특히 Google Maps 소비자 앱의 *Immersive View* 기능을 그대로 외부 서비스에 붙일 수 있다고 가정하면 안 됩니다. MVP는 **공식 개발자용 Street View 등 실제 사용 가능한 기능**을 기준으로 설계합니다.

## 9. 기존 서비스와 어떻게 다른가?

아래 비교는 2026-10-14 기준 공개된 **공식 소개·도움말에서 확인 가능한 대표 기능**을 기준으로 합니다. 모든 기능을 전수 조사한 결과가 아니므로 '최초', '경쟁 서비스에 없음'이라는 표현은 사용하지 않습니다.

| 서비스 | 확인된 강점 | LoreMap이 차별화를 실험할 지점 |
|---|---|---|
| **Google Maps** | Immersive View를 통한 장소·경로 미리 보기, Ask Maps 대화형 탐색 [S1, S2] | 하루 일정의 각 방문 화면에서 **유지·제외 이유를 수집해 코스 변경** |
| **Mindtrip** | 개인화 추천, 여행 일정 만들기·수정, 지도·공동 계획 [S8] | 추천 이후에 **실제 현장 화면을 차례로 체험하며 선택** |
| **DimTrip** | 시간 단위 일정·이동 시간 반영·AI 일정 편집 [S9] | 일정 수정 이전에 **가상 방문이라는 의사결정 단계**를 제공 |

**차별화 가설:** 사용자는 텍스트/사진 목록만 보는 방식보다, **가상 방문 직후 유지/제외를 판단하고 코스를 바로 수정할 때** 여행 계획을 더 쉽게 결정할 수 있을 것입니다.

이 가설이 틀리다면 실질적 경쟁력은 부족합니다. 따라서 단순 AI 이미지 품질보다 사용자 실험으로 검증해야 합니다.

## 10. 리스크와 대응

| 위험 | 왜 문제인가? | 대응 |
|---|---|---|
| **AI 이미지의 부정확성** | 실제 장소가 다르게 보일 수 있음 | 실제 자료 우선, 생성 이미지는 별도 영역·라벨 제공 |
| **콘텐츠 사용 권한** | 지도/사진의 저장·가공·재배포 제한 | 공식 뷰어 사용, 사진 사용·수정 허가 확인, 출처 표시 |
| **360도 자료 부족** | 특정 관광지는 Street View가 없을 수 있음 | 가능한 관광지로 시범 지역 선정, 일반 사진으로 대체 |
| **실제 일정의 오류** | 운영시간·휴무·이동 수단 정보가 달라질 수 있음 | 장소 API 검증, 조회 시점 표시, 누락 시 확인 안내 |
| **실행 비용/속도** | 지도·AI 호출이 많아질 수 있음 | 시작 시 호출 횟수·비용 측정, AI 생성은 1~2곳으로 제한 |
| **실질적 차별점 부재** | 기존 지도+일정 관리와 비슷하게 느낄 수 있음 | 가상 방문 전후 선택 변화와 유용성 검증 |

## 12. 사용자에게 정말 필요한 서비스인지 검증하는 방법

### 실험 설계

같은 지역의 하루 여행 코스 계획 과제를 두 방식으로 진행합니다.

- **A 방식:** 일반적인 관광지 목록, 사진, 지도, 리뷰를 보고 계획
- **B 방식:** LoreMap의 가상 방문과 선택형 코스 수정으로 계획

### 관찰할 지표

| 지표 | 확인하려는 것 |
|---|---|
| 최종 일정 결정에 걸린 시간 | 계획이 더 쉬워졌는가? |
| 장소 변경 횟수와 이유 | 가상 체험이 실제 선택에 영향을 줬는가? |
| '왜 이 장소를 선택했나요?'에 대한 설명 가능 여부 | 방문 결정을 더 명확하게 내렸는가? |
| 사용자 평가: 도움이 되었는가? | 단순한 시각적 재미를 넘는 가치가 있는가? |
| 다시 사용하겠다는 의향 | 반복 이용할 이유가 있는가? |

**초기 성공 기준(팀이 정할 목표값의 예):** 참가자의 과반이 '가상 체험이 장소 선택을 바꾸는 데 도움이 되었다'고 응답하는지 확인합니다. 이것은 **검증 목표**이지 사전에 확인된 수치가 아닙니다.

### 실패로 판단할 신호

- 관광지를 가상으로 둘러보더라도 사용자의 선택이 거의 바뀌지 않음
- 일반 사진을 보는 것과 비교해 실제 의사결정에 도움이 되지 않음
- AI 참고 이미지가 오히려 장소를 오해하게 만듦
- 장소 콘텐츠 확보 비용이 서비스 가치보다 큼

## 13. 결정해야 할 사항

- [ ] 시범 지역 한 곳 선정(관광지 자료 확보가 가능한 곳 우선)
- [ ] 사용자의 핵심 상황 확정: 1일 자유여행 / 가벼운 도보 여행 등
- [ ] 지원할 이동 수단 확정(예: 도보 + 대중교통 중 하나를 우선)
- [ ] 실제 관광지 사진 및 360도 자료 사용 권한 검증
- [ ] AI 이미지 생성에 사용할 적법한 참조 자료 확보 가능 여부 결정
- [ ] 선정 장소의 영업정보·경로 정보 지원 범위 확인
- [ ] 1주차 사용자 인터뷰 질문 확정

## 14. 발표할 때 사용할 짧은 소개문

> **LoreMap은 여행을 떠나기 전에 여행 코스를 미리 체험하고, 그 결과로 방문할 장소를 선택하는 AI 여행 시뮬레이터입니다.**  
> 사용자는 관광지의 실제 사진과 360도 화면을 따라 하루 코스를 가상으로 둘러봅니다. 마음에 들지 않는 장소는 이유와 함께 제외할 수 있고, AI는 그 선택을 반영해 다른 장소와 이동 경로를 제안합니다. AI가 생성한 참고 이미지는 실제 풍경과 구분해 제공합니다. 목표는 관광지를 단순히 추천하는 것이 아니라, 사용자가 **직접 비교하고 판단한 여행 일정**을 완성하도록 만드는 것입니다.
