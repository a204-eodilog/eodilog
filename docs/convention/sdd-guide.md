# spec-kit 사용법

spec-kit은 코드를 쓰기 전에 **명세(무엇을) → 계획(어떻게) → 작업 목록(어떤 순서로)** 을 문서로 만들고, 그 문서대로 AI가 구현하게 하는 도구다.

## 1. 준비

- 최신 `dev`를 pull 받는다. spec-kit은 `frontend/`에 이미 설치돼 있다. 각자 설치할 것은 없다.
- AI 도구(Claude Code)를 **`frontend/` 폴더에서** 연다.
- Git Bash가 있어야 한다. Git for Windows를 설치했다면 이미 있다.

## 2. 기본 흐름

기능 하나를 만들 때 이 순서대로 실행한다.

| 순서 | 명령 | 하는 일 | 생기는 파일 |
| --- | --- | --- | --- |
| 1 | `/speckit-specify` | **무엇을** 만들지 정리 | `spec.md` |
| 2 | `/speckit-clarify` | 명세의 빈 곳을 AI가 질문, 답을 명세에 반영 | `spec.md` 보완 |
| 3 | `/speckit-plan` | **어떻게** 만들지 정리 | `plan.md` 외 설계 문서 |
| 4 | `/speckit-tasks` | **어떤 순서로** 만들지 작업 목록 작성 | `tasks.md` |
| 5 | `/speckit-analyze` | 명세·계획·작업 목록이 서로 맞는지 점검 | 없음. 보고만 한다 |
| 6 | `/speckit-implement` | 작업 목록대로 코드 작성 | 코드, 체크된 `tasks.md` |

**1~5는 문서만 만든다. 코드는 6에서 처음 생긴다.** 6을 실행하기 전에 다른 사람에게 문서 리뷰를 받는다.

## 3. 명령별 입력 예시

명령 뒤에 자연어로 짧게 붙인다.

```text
/speckit-specify 저장 탭에서 내가 저장한 장소를 목록과 지도로 본다. 화면 S10, 흐름 4.2. S11 링크 등록은 이번에 안 한다.
```
무엇을 만드는지 한 문장, 화면 ID와 흐름 절 번호, 이번에 안 하는 것만 적는다. 자세한 내용은 AI가 `docs/flow/` 문서에서 직접 읽는다. 라이브러리·컴포넌트 이름은 쓰지 않는다.

```text
/speckit-clarify
```
입력 없음. AI가 최대 5개까지 하나씩 묻는다. 모르는 질문은 추측하지 말고 문서나 팀에 확인한다.

```text
/speckit-plan 북마크 API가 아직 없으면 mock으로 먼저 만든다.
```
이 기능에만 해당하는 조건을 적는다. 없으면 `/speckit-plan`만 실행한다.

```text
/speckit-tasks
/speckit-analyze
```
입력 없음. analyze가 지적한 내용은 고치고 넘어간다.

```text
/speckit-implement Phase 1까지만
```
한 번에 끝까지 돌리지 말고 단계(Phase)별로 나눠 실행한다. 단계마다 앱에서 확인한다.

## 4. 필요할 때만 쓰는 명령

| 명령 | 언제 |
| --- | --- |
| `/speckit-constitution` | 팀 공통 원칙(`constitution.md`)을 정하거나 바꿀 때. 혼자 실행하지 않는다 |
| `/speckit-checklist` | plan 후 접근성·오류 처리처럼 따로 점검할 관점이 있을 때 |
| `/speckit-converge` | implement 후 명세 대비 빠진 구현이 보일 때. 남은 작업을 `tasks.md`에 추가한다 |
| `/speckit-taskstoissues` | 쓰지 않는다. GitHub 이슈용이다 |

## 5. 명세는 기능별로 하나씩

`/speckit-specify`는 **기능 하나마다 따로** 실행한다. 한 번 실행하면 `specs/<날짜-시각>-<기능이름>/` 폴더가 하나 생기고, 이후 명령은 그 폴더 안에서만 움직인다.

- **기능 하나 = 사용자가 처음부터 끝까지 해낼 수 있는 일 하나.** 화면 하나, 컴포넌트 하나가 아니다.
- **user-flow.md의 하위 절 하나(4.1, 4.2 …)를 명세 하나로** 잡는다. 화면 1~3개 정도다.

| 크기 | 예 |
| --- | --- |
| 너무 작음 | 장소 카드 컴포넌트 → 명세 안의 작업 하나 |
| 적당함 | 링크로 장소를 추출해 저장한다 (S11~S13, 흐름 4.1) |
| 너무 큼 | 저장 탭 전체와 여행 후 정리 → 나눈다 |

## 6. 주의

- **명령은 `/speckit-`까지 붙여 쓴다.** 예전 버전의 `/specify`, `/plan`이나 다른 도구용 `/speckit.plan`(점)은 지금 쓰지 않는다. 입력창에 `/spec`까지 치면 목록이 뜬다.
- **AI가 만든 문서는 단계마다 직접 읽는다.** AI는 빈 곳을 그럴듯하게 채운다. 이상하면 다음 단계로 가지 말고 그 자리에서 고친다.
- **구현 중 결정이 바뀌면 `spec.md`·`plan.md`도 같이 고친다.**
- `.specify/feature.json`은 각자 작업 중인 명세를 가리키는 개인 파일이라 커밋하지 않는다.
