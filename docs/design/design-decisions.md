# 어디로그 디자인 결정 (제안)

> Figma 어디로그(파랑) 페이지를 다듬으며 정한 화면 기준과 화면별 결정이다. 화면을 구현할 때 [화면 목록](../flow/screen-list.md)·[사용자 흐름](../flow/user-flow.md)과 함께 본다.
> 기능·정책은 PRD와 결정 기록이 기준이다. 이 문서는 **보이는 방식**만 다루며, 기능을 새로 만들지 않는다.

**상태 표시**

| 표시 | 뜻 |
| --- | --- |
| `근거` | PRD·화면 목록·결정 기록에 이미 있는 내용을 화면에 맞춘 것 |
| `FE 제안` | 이번 디자인 수정에서 정한 것. MR 리뷰로 합의하며, 합의 전까지는 참고용이다 |

## 1. 화면 공통 기준

| 기준 | 내용 | 상태 |
| --- | --- | --- |
| 말 거는 제목 | 화면 맨 위 큰 제목은 기능 이름보다 사용자에게 말을 거는 문장으로 쓴다. 예: "어떤 여행을 떠나시나요?", "OO님, 이제 코스만 짜면 돼요". 이름·D-day 같은 핵심 값만 파랑으로 강조한다 | `FE 제안` |
| 상자 줄이기 | 카드 안에 카드를 넣지 않는다. 같은 성격의 항목은 회색 상자 대신 흰 바탕 + 구분선으로 나눈다 | `FE 제안` |
| 안내 문구 | 규칙 설명("동행 누구나 ~할 수 있어요" 등)은 꼭 필요한 곳만 남긴다. 개인정보 안심 문구("연령은 공개 프로필에 보이지 않아요" 등)와 화면 목록에 적힌 필수 안내는 남긴다 | `FE 제안` |
| 주요 버튼 | 화면의 주 행동 버튼은 좌우 여백을 뺀 전체 폭, 높이 56, 모서리 16. 보조 행동은 글자 버튼 | `FE 제안` |
| 헤더 아래 여백 | 상단 제목(헤더)과 본문 첫 요소 사이 16. 맨 위가 지도·파랑 블록인 화면은 붙인다 | `FE 제안` |
| 바텀시트 | 화면 맨 아래에 붙인다. 내용 카드와 버튼 사이 20 | `FE 제안` |
| 여행 헤더 | 여행 상세(S17)·여행 목록 카드(S15)·초대(S04)는 파랑 블록 위에 흰 글씨. 다녀온 여행만 여행 사진을 쓴다 | `FE 제안` |
| 로딩 | 결과를 기다리는 화면은 가운데에 아이콘(또는 물결 마커)·제목·진행 단계를 모아 둔다. 지도처럼 아직 의미 없는 배경은 쓰지 않는다 | `FE 제안` |
| 회색 카드 | 마이페이지·기록 화면의 카드는 흰 바탕 + 얇은 테두리 + 옅은 그림자. 작은 상태 태그(비공개·게시 전 등)만 회색 | `FE 제안` |

### 1.1 사진

- `근거` API 초안에서 사진이 있는 데이터는 **여행 사진**(여행 후 동행이 올림)과 **공동 피드 사진·표지**뿐이다. 여행·장소·지역·추천 장소에는 사진 필드가 없다. 여행 전에는 그 여행의 사진이 없다.
- `FE 제안` 그래서 사진은 위 두 가지에서만 쓰고, 사진이 없는 자리는 파랑 블록이나 종류 아이콘으로 그린다.
- `FE 제안` 사진이 더 있음을 알리는 "+N" 칸은 남은 사진 4장을 2×2로 깔고 어둡게(50%) 덮은 뒤 숫자를 얹는다.
- Figma에 들어간 예시 사진은 출처가 확인되지 않았다. 발표 자료에 쓸 때는 출처가 확실한 사진으로 바꾼다.

## 2. 화면별 결정

| 화면 | 결정 | 상태 |
| --- | --- | --- |
| S03 취향 입력 | "사진으로 더 골라 보세요" 사진 묶음 대신 누르면 추가되는 추천 칩. 칩 목록은 예시이며 Q-5 결정 후 바꾼다 | `FE 제안` |
| S04 초대 참여 확인 | 여행 정보를 파랑 카드 안에 넣는다. "동행이 공동 피드로 게시하면 모두에게 공개될 수 있어요" 안내를 둔다 | `근거`(화면 목록 S04) |
| S05 홈 | 첫 화면은 지금처럼 물든 지도 + 지역 핀. 지도를 확대하면 시군 단위 사진 핀(그 지역에서 가장 최근 게시된 여행의 표지 1장 + 지역 이름 + 다녀간 친구 얼굴)으로 바뀐다. 전국 보기 버튼은 두지 않는다(손가락으로 확대·축소). 친구 얼굴은 `/home/map`의 친구 ID를 팔로잉 목록과 맞춰 표시한다 | `FE 제안` |
| S07 친구 여행 상세 | 경로 칸은 실제 지도 위에 장소 번호 핀과 이동 경로 선(일차별 색 구분). 경로 좌표가 없는 구간은 점선 직선 | `근거`(WD-FR-26, `RouteLeg.geometry`) |
| S10 저장 없음 | 빈 화면 그림은 "링크 칩 → 저장 핀"만. 지도 배경 없음 | `FE 제안` |
| S12 추출 진행 중 | 지도 없이 흰 화면 가운데에 물결 마커(움직임) + 제목 + 진행 단계 + 취소 | `FE 제안` |
| S15 여행 목록 | 다가오는 여행 카드는 파랑 블록 + D-day. API는 만든 순서로 내려주므로 앱이 출발일 기준으로 다가오는 여행을 고른다 | `FE 제안` |
| S16 새 여행 만들기 | 큰 질문 "어떤 여행을 떠나시나요?", 이름은 밑줄 입력, 기간·여행지는 "언제 / 어디로" 줄(값이 없으면 "나중에 정할게요"), 전체 폭 [여행 만들기] | `FE 제안`(기간·여행지 선택 입력은 `근거` F-11) |
| S17 여행 상세 | 파랑 블록에 여행 이름·말 거는 큰 제목·날짜 칩·동행 얼굴·초대 버튼. 아래에 "OO님, …" 인사 + 단계 3개(지금 단계에 버튼) + 여행 메뉴 아이콘 격자. 단계는 여행 상태에서 계산한다 | `FE 제안`(상태별 지금 할 일은 `근거` F-17) |
| S21 추천 결과 | "이번 추천에 쓴 것"은 숫자 칸 3개(모은 장소·겹침 / 공개 취향 인원 / 여행지·기간). 값은 추천 결과 `basis`에서 가져온다 | `FE 제안` |
| S22 투표 | 위 카드는 "N일 남았어요"만, 후보 제목은 "후보 N곳 · 여러 곳 골라도 돼요", 후보 카드에서 출처 줄은 뺀다 | `FE 제안` |
| S23 직접 만들기 | 즐겨찾기 장소를 끌어 날짜 칸에 놓으면 그 날짜 끝에 들어간다("장소 놓은 뒤" 상태) | `근거`(화면 목록 S23) |
| S23 구성 방식 선택 | "어떻게 짤까요?"는 작은 회색 소제목(화면 제목 "코스 짜기"보다 약하게) | `FE 제안` |
| S35·S36 경비·정산 | 경비 목록에는 합계와 지출 줄만. 1명당 금액·사람별 낸 돈은 정산 결과(S36)에만. S36에 "1명 금액은 10원 단위로 올려 계산했어요" | `근거`(결정 Q-10, 정산 완료 없음 v0.4) |
| S39 피드 게시 | 동행 사진 동의 문구 없음 | `근거`(결정 F-20) |
| S45 설정 | AI 기능 초기값은 모두 '확인 후', 날씨는 '제안만'. 방문 장소 찾기는 '자동'을 막는다(판정 기준 합의 전) | `FE 제안`(API 초안 D-19를 따름) |
| S46 대화방 없음 | [새 대화] 대신 [여행 만들기]→S16 | `근거`(1:1 채팅 없음, 결정 Q-13) |
| S47 시스템 메시지 | 코스 확정·승인 요청 카드 없음. 투표는 "마감 시각에 확정" | `근거`(결정 F-14·F-15) |
| S48 알림 팝업 | 알림이 여러 개면 줄마다 눌러 해당 화면으로 가고, 아래 버튼은 [알림 모두 보기]→S49 | `FE 제안` |
| S50 나가기 | 영향 안내는 한 줄 짧게("경비 기록은 남아요" 등) | `FE 제안` |
