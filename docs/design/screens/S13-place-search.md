# S13 장소 직접 검색·지정

담당 A · 핵심 · 요구사항 WD-FR-05 · 여는 곳 S12, S20, S23, S31, S32 (장소를 고르는 모든 화면)

화면 규칙은 [화면 목록](../../flow/screen-list.md) S13 줄: 장소 검색, 지도에서 고르기. 구현은 MR !115(`frontend/src/features/place`).

> **이 화면의 약속: 검색에 없는 장소는 사용자가 지도에서 직접 찍고 이름을 적어 만든다.** 이렇게 만든 장소는 사용자가 입력한 좌표와 이름만으로 이루어진 **수동 장소**(`source: MANUAL`)이고, 즐겨찾기·투표·코스 어디에나 검색으로 고른 장소와 똑같이 쓴다. 검색 결과를 어떤 공급자가 주는지와 상관없이 지켜지는 규칙이라, 장소 검색 공급자가 바뀌어도 이 화면과 부른 화면은 바뀌지 않는다.

## 다른 화면에서 쓰는 법

```ts
import { pickPlace } from '@/features/place/place-picker';

const place = await pickPlace({ regionId, near: { latitude, longitude } }); // 둘 다 선택
if (place) save(place.id); // 뒤로 나가면 null
```

- 검색에서 고르거나 지도에서 직접 만들면 `Place`(우리 `places.id`), 뒤로 나가면 `null`. 검색 → 지도에서 고르기로 넘어가도 같은 약속이 이어진다.
- 한 번에 하나만 열린다. 열려 있는데 또 부르면 앞의 것은 `null`로 끝난다.
- 부른 화면은 받은 `Place`의 `source`를 구분하지 않아도 된다. 수동 장소도 `id`·`name`·좌표가 있다.

## 검색 결과

1. **상단 바** — 높이 56, 제목 없이 [뒤로] 44 옆에 검색칸이 한 줄로 붙는다(왼쪽 8, 오른쪽 20, 간격 6)
2. **검색칸** — 남는 너비 전체, 알약(높이 40, 배경 `colors.surface.default`, 입력 중 테두리 `colors.brand.primaryLight`). 돋보기 20 + 입력 `typography.body`(자리 글 "장소 이름으로 찾기" `colors.text.muted`) + 글자가 있으면 오른쪽 [지우기] 28(회색 동그라미). 글자를 멈추고 300ms 뒤 검색, 이전 요청은 취소. 검색어 최대 100자(명세에 없어 화면에서 정함)
3. **지도에서 직접 고르기 카드** — 위 12, 배경 `colors.brand.primaryBg`, 둥글기 `radius.lg`, 안쪽 14/16. 지도 아이콘 20 `colors.brand.primaryDark` + "지도에서 직접 고르기" `typography.bodyBold` `colors.brand.primaryDark` + 오른쪽 `Icon chevron-right`. 결과가 있어도 항상 보인다
4. **결과 수** — "검색 결과 N곳" `typography.captionMedium` `colors.text.icon`
5. **장소 줄** — 높이 64, 핀 아이콘 20 + 이름 `typography.bodyBold`(한 줄) + 주소 `typography.caption` `colors.text.icon`(한 줄, 없으면 생략). 누르면 그 장소를 부른 화면에 돌려주고 닫힘. 한 번에 20곳(첫 페이지만)

## 지도에서 고르기 (수동 장소)

1. **상단 바** — [뒤로], 제목 "위치 고르기"
2. **지도** — 남는 높이 전체. 가운데에 고정 핀(`CenterPin`), 위 16에 안내 띠 `MapHint` "지도를 움직여 위치를 맞춰 주세요". 부른 화면이 `near`를 줬으면 그 주변(0.03도 범위), 없으면 한국 전체
3. **아래 시트** — 흰 바탕, 위 둥글기 `radius.xxl`, 좌우 20, 세로 간격 16, 위에 손잡이 36x4 `colors.gray[300]`
   1. "이 위치가 맞나요?" `typography.title1`, 간격 2, [핀 아이콘 16 + "지도 가운데 · 35.1532, 129.1186"] `typography.caption` `colors.text.icon`
   2. **장소 이름** — 공통 `TextField variant="filled"`(높이 52), 자리 글 "예: 민락 수변공원", 최대 255자(ERD `places.name`). 필수. 비우고 누르면 칸 아래 "장소 이름을 적어 주세요"
   3. **버튼** — 오른쪽 알약 주 버튼 48 [체크 20 + "이 위치로"]. 저장 중이면 로딩
4. 저장 실패 → 토스트 "장소를 만들지 못했어요" + [다시 시도]

**사용자가 입력하는 것은 좌표(지도 가운데)와 이름 둘뿐이다.** 주소는 좌표로 주소를 찾는 API가 명세에 없어 지금은 좌표 숫자로 보여 준다. 생기면 "부산 수영구 민락동"처럼 바꾼다(화면 표시용. 저장 여부는 백엔드 결정).

### 수동 장소가 할 수 있는 것과 한계

| | 내용 |
| --- | --- |
| 할 수 있는 것 | 즐겨찾기·그룹 즐겨찾기·투표·코스에 넣기, 지도 핀(저장한 좌표), 이름 표시. 검색으로 고른 장소와 같은 `Place` |
| 한계 | 이름은 사용자가 적은 그대로(오타·"카페" 같은 대충 적은 이름 가능). 전화·영업시간 같은 상세 없음. 다른 사용자가 같은 가게를 또 찍으면 별개 장소가 될 수 있음(합치는 규칙은 백엔드) |
| 언제 쓰나 | 검색 결과에 없을 때, 검색이 오래 걸릴 때, 지도에서 바로 위치를 찍고 싶을 때. 결과가 있어도 카드가 항상 보인다 |

## 공통 부품과 맞지 않는 점

- 검색칸 알약은 S16 여행지 검색과 같은 모양이다. 공통으로 떼면 함께 쓴다.
- 결과 없음·오래 걸림은 README "가운데 안내 화면"과 같은 구조인데, 오래 걸림은 주 버튼 아래 글자 버튼 "지도에서 고르기"가 하나 더 있다.
- 지도·가운데 핀·안내 띠는 지도 공통 부품(!110)이다.

## 그 밖의 상태

- **검색 결과 없음** — 가운데 안내: 제목 "검색 결과가 없어요", 설명 "지도에서 직접 골라 주세요", 주 버튼 [지도에서 고르기]
- **검색 오래 걸림** — 8초 초과 또는 503 `PROVIDER_UNAVAILABLE`: 제목 "검색이 오래 걸려 멈췄어요", 설명 "검색이 오래 걸려요", 주 버튼 [다시 검색], 글자 버튼 "지도에서 고르기"
- **그 밖의 실패** — 공통 `ErrorState` "장소를 찾지 못했어요" + [다시 검색]
- 검색어를 바꿔 이전 요청이 취소된 것은 실패로 보지 않는다

## 버튼과 이동

| 누르는 것 | 어디서 | 동작·이동 |
| --- | --- | --- |
| 검색칸 입력 | 검색 결과 | 300ms 뒤 `GET /places?query=&limit=20&regionId=`(regionId는 있을 때만) |
| 장소 줄 | 검색 결과 | 부른 화면에 `Place` 돌려주고 닫힘 |
| 지도에서 직접 고르기 카드 / [지도에서 고르기] | 검색 결과·결과 없음·오래 걸림 | 지도에서 고르기로 바꿔 열기(`replace`). 부른 화면과의 약속은 이어짐 |
| [다시 검색] | 오래 걸림·실패 | 같은 검색어로 다시 `GET /places` |
| [이 위치로] | 지도에서 고르기 | `POST /places { name, latitude, longitude, regionId? }` → 수동 장소 `Place` → 부른 화면에 돌려주고 닫힘 |
| [뒤로] | 둘 다 | 부른 화면에 `null` |

## 백엔드에 필요한 것 (2026-11-04 기준 없음)

- 좌표 → 주소 API(지도에서 고르기의 주소 표시). 없어도 화면은 좌표로 동작한다
